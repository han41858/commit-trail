# Commit Trail — Monitor Mode v0.1

## 목적과 범위

일반 모드를 유지하면서 1~32개 GitHub 저장소의 기존 세로형 Git DAG를 한 가로 행에서 관찰한다. 모바일 PWA 가로 화면을 권장하며 데스크톱과 세로 화면도 지원한다. 새로운 백엔드·라이브러리·그래프 엔진·Worker·Service Worker는 도입하지 않는다.

## 진입과 저장소 선택

- 일반 헤더의 분할 아이콘 **Split view**로 선택 창을 연다. 직전 Split view 구성이나 저장한 선택이 있으면 항목과 순서를 그대로 복원하며, 사용자가 제거한 현재 저장소를 다시 추가하지 않는다. 기존 구성이 없는 최초 선택에만 현재 저장소를 기본값으로 넣는다. URL에서 복원한 구성은 저장된 기본 선택보다 우선한다.
- 최근 방문 목록을 재사용하거나 `owner/repo`·GitHub URL을 직접 입력해 추가한다. 주소는 기존 `parseRepo`·소문자 변환·커서 보존 로직을 사용한다. 최근 항목 선택과 완성된 저장소 주소 추가는 API를 호출하지 않으며, Owner 단독 제출은 아래의 명시적 목록 조회를 실행한다.
- 선택 창 아래 **Recent repositories** 항목은 저장소 이름만 표시하며 앞쪽 화살표는 표시하지 않는다. 일반 저장소 입력창 자동완성의 최근 방문 아이콘은 유지한다.
- 중복과 32개 초과 선택을 막는다. 선택한 항목은 아래 최근 목록에서 숨기며, 위 목록에서 제거하면 아래에 최근 방문 순서대로 다시 나타난다. 32개가 선택되면 추가 가능한 최근 목록을 숨긴다.
- **선택 창 위쪽 목록**의 핸들을 마우스·터치로 드래그해 순서를 바꾼다. 키보드에서는 핸들에 포커스를 두고 ↑/↓를 사용한다. 포커스를 유지하며 변경한 위치를 스크린 리더용 상태로 알린다. 이 순서가 분할 화면의 좌우 배치·저장된 선택·공유 링크에 반영된다. 활성 분할 화면에서는 아래 헤더 핸들로 드롭 시점에만 순서를 변경한다.
- 최소 한 개를 선택해야 **Start split view**와 **Copy link** 버튼이 활성화된다. 이미 표시된 저장소의 선택·추가·제거·정렬·링크 복사는 API 요청을 발생시키지 않는다. Owner 조회와 추가 페이지 요청은 별도의 명시적 조회 동작이다.
- 선택 창은 제목·닫기와 하단 개수·**Copy link**·**Start split view**를 고정하고, 가운데 저장소 목록·추가 입력·최근 목록 영역만 스크롤한다. 높이가 낮은 창이나 가로 화면에서 저장소가 많아도 시작 버튼에 스크롤 없이 접근한다. 목록 드래그의 가장자리 자동 스크롤도 가운데 영역을 사용한다. 최근 목록에 별도 스크롤을 두지 않으며, 가운데 영역의 사방 4px 여백과 스크롤 여백으로 정렬 핸들·입력창·버튼의 포커스 링이 잘리지 않게 한다. Escape·닫기·배경 클릭으로 닫을 수 있고, 키보드 포커스를 창 안에서 이동한 후 기존 진입 버튼으로 돌려준다.
- 모니터 모드 안에는 저장소 추가·삭제·브랜치 선택·방향 전환·설정 UI를 제공하지 않는다. 헤더 핸들은 순서 변경만 제공한다. 수동 갱신은 상단의 공통 새로고침 버튼을 사용한다.

Owner만 입력하고 Enter 또는 **Add**를 누르면 일반 화면과 같은 조회·필터·페이지 처리를 사용하는 저장소 목록을 연다. Split view에서는 별도 테두리·제목줄·닫기 버튼 없이 기존 설정 창 본문에 검색과 체크리스트를 이어 붙이고, 중첩 대화상자가 아닌 이름 있는 영역으로 제공한다. 여러 저장소를 체크한 뒤 **Add N repositories**를 누르면 기존 선택 순서를 유지하며 체크한 순서대로 뒤에 추가한다. 체크·체크 해제·일괄 추가 자체는 API를 호출하거나 그래프를 열지 않는다.

이미 추가된 저장소는 체크된 비활성 항목과 **Already added**로 표시한다. 기존 항목과 추가 예정 항목의 합계는 최대 32개이며, 필터 변경이나 **Load more** 후에도 미확정 체크는 유지한다. 목록을 닫거나 Owner·PAT·입력 컨텍스트가 바뀌면 미확정 체크를 버린다. Owner 목록의 Escape는 목록만 닫고 설정 창을 유지한다. Owner 조회·체크만으로 저장된 구성·공유 URL·최근 방문 기록을 변경하지 않으며, 확정 추가 후 저장·공유·드래그는 기존 선택 목록 정책을 따른다. 상세 정책은 [Owner 저장소 선택](owner-repositories.md)을 따른다.

## URL 구성 공유와 복원

| URL 예시                                                                       | 동작                                    |
| ------------------------------------------------------------------------------ | --------------------------------------- |
| `/?repo=han41858/commit-trail`                                                 | 기존 단일 저장소 화면                   |
| `/?repo=han41858/commit-trail&repo=octocat/Hello-World`                        | URL 순서대로 두 저장소 분할             |
| `/?repo=han41858/commit-trail&mode=monitor`                                    | 한 저장소로 분할 모드 진입              |
| `/?repo=han41858/commit-trail&repo=octocat/Hello-World&branch=dev&branch=main` | 각 저장소를 `dev`, `main` 기준으로 복원 |
| `/?repo=han41858/commit-trail&repo=octocat/Hello-World&branch=&branch=main`    | 첫 저장소는 자동 선택, 두 번째는 `main` |

- `repo` 파라미터가 두 개 이상이거나 `mode=monitor`이면 모니터 구성을 읽는다. 기존 파서로 주소를 정규화하고 소문자 변환·중복 제거 후 앞쪽의 유효한 저장소를 최대 32개까지 사용한다. 중복·잘못된 항목 제거 후 하나만 남아도 모니터 의도를 유지하며, 유효한 항목이 전혀 없으면 빈 일반 화면을 표시한다.
- 파싱은 접근 권한을 확인하지 않는다. 실제 진입에서는 기존 모델로 각 저장소를 열고, 권한·404·네트워크 오류는 해당 열에만 표시한다. 첫 저장소가 실패해도 나머지 열은 동작하며 기존 공통 갱신으로 다시 시도한다. 부분 목록 밖의 URL·저장된 브랜치 후보에 한해서 기존 정확한 이름 조회를 재사용하며 공개 여부 확인용 추가 요청은 없다.
- 일반 모드의 선택 창에만 **Copy link**를 제공한다. 현재 선택과 순서를 반복 `repo` 파라미터로 만들며, 한 개일 때는 `mode=monitor`를 넣는다. 실제 클립보드 복사가 성공하면 버튼에 **Copied!**, 거부·미지원이면 **Copy failed**를 표시하며 2초 뒤 **Copy link**로 돌아온다. 별도 진행 문구는 표시하지 않으며 처리 중 재클릭을 막는다. 기존 상태 영역에서도 성공·실패를 알린다. 선택/순서 변경 시 피드백을 초기화하고 이전 복사의 늦은 결과는 표시하지 않는다. 복사만으로 모드를 시작하거나 현재 주소를 바꾸지 않는다.
- 공유 링크에는 저장소 이름·순서·모드와 확인된 현재 기준 브랜치를 포함한다. 반복 `branch`는 `repo`와 인덱스로 대응하며 미확인 중간 값은 빈 위치로 유지한다. 잘못된 저장소·중복 제거 시 브랜치도 함께 제거한다. 원래 주소의 다른 쿼리·해시·URL 인증 정보는 제거하며 PAT·자동 갱신 주기·디버그·스크롤 상태는 복사하지 않는다. **비공개 저장소·브랜치 이름도 URL에 노출된다**. 링크 접근 시에는 수신자의 기존 PAT·인증 정책을 그대로 적용한다.
- 모드·저장소 전환은 브라우저 history에 기록하며 뒤로/앞으로 가기와 새로고침은 URL 구성을 복원한다. 저장된 선택은 URL 구성을 덮어쓰지 않는다. 기존 `?debug=1` 등 현재 탭의 부가 URL 문맥은 앱 안의 이동에서는 유지하지만 공유 링크에서는 제외한다.
- 새 탭에서 모니터 URL을 열면 첫 저장소를 기본 모델로 사용한다. 기존 일반 화면에서 진입한 경우 기본 모델·Canvas·탐색 상태를 보존하고 명시적인 URL 브랜치 변경만 적용한다. 복귀 시 그 저장소와 현재 기준 브랜치의 단일 URL로 돌아간다. 새로고침 후에는 URL의 첫 저장소가 복귀 대상이며 이전 탭의 스크롤·커밋 선택은 공유하지 않는다. URL로 복원한 선택은 로컬의 마지막 직접 선택을 덮어쓰지 않는다.
- URL 진입도 현재 창의 레이아웃만 전환한다. Fullscreen API나 새 라우터·라이브러리는 사용하지 않는다.

## 저장과 인증 경계

- localStorage 키는 `commit-trail.monitor-repositories`이며 최대 32개의 정규화된 저장소 **이름 문자열 배열만** 저장한다. PAT·토큰 일부·해시·API 응답·커밋·스크롤 위치는 포함하지 않는다.
- 잘못된 배열·주소·중복 항목은 정리한다. 저장소 접근 실패 시에도 모니터링은 현재 탭의 메모리에서 사용할 수 있다.
- 공개 여부는 최근 방문 이력의 실제 API 메타데이터 분류를 재사용한다. PAT를 쓰지 않는 직접 입력 항목은 공개 메타데이터 조회 성공 후 저장 목록에 반영한다.
- 최초 PAT 등록·교체·삭제 시 비공개 및 공개 여부를 확인할 수 없는 선택을 제거하고, 확인된 공개 선택만 유지한다. 동일 PAT 재적용과 저장된 같은 PAT 복원은 선택을 유지한다. 접근 실패만으로 목록을 삭제하지 않는다.
- 목록 자체가 접근 권한을 보장하지 않는다. 새 토큰으로 다시 조회한 비공개 저장소는 다시 선택·등록할 수 있다.
- 오래된 인증 탭은 적용 토큰과 저장 토큰의 일치 여부를 확인해 다른 인증의 비공개 선택을 표시하거나 덮어쓰지 않는다. 다른 탭의 PAT 변경 이벤트는 모니터 모드와 선택 창을 닫고 선택을 다시 읽는다. 실제 적용 토큰을 몰래 바꾸지는 않는다.
- 최근 방문 목록은 기존 10개를 유지한다. 선택한 공개 저장소가 이 목록에서 밀려나도 32개 선택을 복원할 수 있도록, 실제 메타데이터로 확인된 공개 이름만 `commit-trail.monitor-public-repositories`의 최대 32개 이름 배열에 함께 보존한다. 제품명 변경 전의 저장 키는 읽거나 이전하지 않으므로 Split view 선택은 다시 설정한다. 배열 형식은 유지하고 확인용 API 요청은 추가하지 않는다. 비공개로 변경된 이름은 공개 분류에서 제거하며 PAT 변경 시 비공개·미확인 이름은 기존처럼 제거한다. 토큰·API 응답은 이 보조 키에도 저장하지 않는다.

## 레이아웃과 복귀

- 선택한 1~32개 모두를 N×1 가로 한 줄로 균등 분할한다. 1·3·4·8·16·32개도 같은 정책이며 최소 열 너비·가로 스크롤·여러 행·화면 크기나 방향에 따른 자동 개수 조정·저장소 숨김은 도입하지 않는다. 각 열은 `min-width:0`과 독립 세로 스크롤을 사용한다. 아주 좁은 화면에서 이름과 메시지를 읽기 어려운 것은 사용자가 선택한 정보 밀도로 허용한다.
- 각 영역 상단의 `owner/repo`는 밑줄이 있는 GitHub 저장소 링크이며 넓은 화면 14px·좁은 화면 13px로 표시한다. 링크의 클릭 범위는 표시된 텍스트 크기로 제한하고 열의 빈 공간·여백은 링크로 처리하지 않는다. 새 탭으로 열어 기존 분할 화면을 유지하며 `noopener noreferrer`를 적용한다. 긴 이름은 말줄임하고 링크 title과 그래프 영역의 접근성 이름에는 전체 값을 제공한다.
- 저장소 이름·공통 새로고침 버튼·복귀 아이콘 **Return to single view**를 하나의 가로줄에 배치한다. 이름은 각 그래프 열과 같은 순서·너비로 정렬하고 왼쪽 새로고침과 오른쪽 복귀 버튼의 공간을 비워 겹침을 막는다. 두 버튼은 저장소 이름 영역보다 앞에서 입력을 받는다. 로고·일반 헤더·일반 상태 패널을 숨긴다. 명시적으로 켠 개발자 진단 UI와 기존 PWA 업데이트 안내는 별도 기존 기능이다.
- **Start split view**는 현재 앱 창을 그대로 분할한다. Fullscreen API 호출이나 전체화면 이벤트 구독은 하지 않는다. 사용자가 원하면 브라우저의 F11 등으로 전체화면을 직접 제어하며 앱의 분할 상태와 독립적이다.
- 복귀 버튼은 일반 모드로 돌아간다. Escape는 드래그·브랜치 툴팁·포커스된 그래프의 고정 강조·열린 팝업 등 현재 입력을 처리하는 대상을 먼저 닫거나 해제한다. 이때 분할 모드를 함께 종료하지 않으며, 처리할 대상이 없을 때 일반 모드로 돌아간다. 경로 입력 우선순위는 [공통 명세](dag-hover-highlight.md#입력과-수명)를 따른다. 브라우저 전체화면을 켜거나 끄는 동작은 앱 모드를 바꾸지 않고, 앱에서 복귀해도 사용자가 설정한 브라우저 전체화면을 종료하지 않는다.
- 강제 화면 회전·방향 잠금은 하지 않는다. Safe Area와 기존 앱 셸의 높이를 사용하며, ResizeObserver가 각 열의 Canvas 크기를 다시 측정한다.
- 개수 제한은 `MonitorRepositories.ts`의 공통 `MONITOR_LIMIT` 한 곳에서 관리한다. 선택 UI·저장·URL 정규화·공유·세션이 이를 재사용하고, 중복·잘못된 입력을 제거한 뒤 앞쪽 32개를 유지하며 대응 브랜치 인덱스도 함께 보존한다. 선택 목록이 길면 가운데 영역을 스크롤해 추가·제거·정렬하고, 복사·시작 버튼은 하단에 항상 표시한다.

## 그래프와 상세

- 현재 열린 저장소가 포함되면 기존 `History`·`CommitInfoStore`·Canvas 인스턴스를 그대로 사용한다. 진입을 위해 같은 메타데이터를 다시 조회하지 않는다. 현재 브랜치·시간 방향·스크롤·선택을 유지한다.
- 추가 저장소는 독립적인 기존 `History`·`CommitInfoStore`를 생성하고 URL 지정 → 마지막 직접 선택 → 기존 `main`·`master`·GitHub 기본 브랜치 우선순위와 최신순에서 시작한다. 모델·커밋 배열·캐시·스크롤은 저장소별로 유지하며, 상세 팝업의 선택만 앱에서 저장소·커밋 한 쌍으로 관리한다. 별도 브랜치 선택 UI는 추가하지 않는다.
- DAG 배치·레인·브랜치 배지·실제 부모 SHA 관계·태그/릴리즈 아이콘·Actions 링은 일반 화면과 같은 렌더러를 사용한다. 경로 소유권·결정적 8색 배정·재현성의 조건과 한계는 [공통 경로 명세](dag-hover-highlight.md)를 따른다. 추가 저장소도 메타데이터 성공 시 태그·릴리즈·Actions 로딩을 병렬 시작해 보이는 커밋의 작업 수를 추적한다.
- 메시지·SHA·작성자와 브랜치 배지는 일반 화면의 기존 반응형 렌더링 정책으로 통일한다. 같은 커밋을 가리키는 브랜치는 일반 화면과 같이 개별 배지를 세로로 나열하고 `+N`으로 생략하지 않는다. 묶음 높이로 겹침을 피하며 매우 큰 묶음의 모든 이름은 그래프 스크롤로 확인한다. 분할 모드는 전체 창 대신 **각 열의 실제 너비**로 기존 800px 기준을 적용한다. 800px 이하의 열은 메시지를 한 줄로 표시하되, 그래프 영역을 최대 50%로 제한했을 때 기존 최소 레인 간격 12px를 확보할 수 없으면 메시지를 숨기고 전체 열을 그래프에 사용한다. 800px 초과의 열은 기존 넓은 화면 표시대로 메시지와 SHA·작성자를 표시한다. 일반 화면의 너비 판단·간격·말줄임 정책은 변경하지 않는다.
- 열이 기존 좌측 기준점 48px보다 좁아지면 분할 그래프의 시작점만 해당 열 중앙으로 보정해 노드가 통째로 화면 밖으로 밀리지 않게 한다. 레인 계산·간격·행 높이는 변경하지 않고 일반 모드와 기존 너비의 분할 그래프는 그대로 유지한다. 헤더 여백도 열 너비 안으로 줄여 이름 영역과 그래프 열의 균등 너비를 유지한다.
- 행 간격은 31px이며 커밋·메시지·태그/릴리즈 아이콘은 상세를 연다. 커밋당 버전 아이콘과 모든 태그·릴리즈의 상세 표시는 [메타데이터 명세](auto-refresh-and-metadata.md#5-git-태그-표시)를 따른다. Hover·배지·선 클릭·고정 강조·선택 해제·불투명도는 [공통 입력 수명](dag-hover-highlight.md#입력과-수명)을 따른다. 다른 열의 배지·선 고정 강조는 유지하며, 크기·순서 변경은 Hover만 해제하고 유효한 고정 대상을 보존한다.
- 강조 대상 변경·해제 시 일반 화면과 같이 불투명도를 약 140ms 동안 전환한다. 빠르게 다른 커밋으로 옮겨도 현재 밝기에서 이어지며 Canvas와 DOM Actions 링은 같은 시간·배율을 사용한다. 열마다 독립 처리하고 전환이 끝나면 추가 그리기는 중단한다. 새 설정·타이머·API 요청이나 프레임별 React 상태·DAG 레이아웃 갱신은 추가하지 않는다.
- 연결선 Hover도 일반 화면과 같이 실제 곡선의 5 CSS px 이내에서 같은 흐름 강조를 적용한다. 첫 부모 선은 자식 흐름, 병합 유입선은 해당 부모의 공통 색상 경로를 시작 경계까지 따라가고 선택한 병합점만 포함하며 노드·배지·메시지가 우선한다. 거의 겹치는 선은 현재 강조 흐름을 유지하고 구분 불가 시 임의로 선택하지 않는다. 선 경로는 각 열의 화면 구간과 좌표로 재사용하며 다른 열에 영향을 주지 않는다. 클릭·탭은 해당 경로 강조만 유지하며 상세 조회를 시작하지 않는다.
- 브랜치 배지는 노드·Actions 링과 여백을 두고 자기 경로 양옆의 가까운 공간과 경로를 따른 대체 위치를 먼저 찾는다. 짧은 경로는 기존 한 행 범위 안의 위아래도 확인하며, 가까운 공간이 없을 때만 먼 가로 위치를 사용한다. 배경은 일반 모드와 같은 약 40% 불투명도로 표시하고 글자는 선명하게 유지한다. 불가피하게 겹치는 좁은 열에서도 노드·링의 클릭과 Hover를 우선한다.
- 상세 패널은 해당 열의 중앙을 기준으로 최대 480px까지 넓혀 인접 열의 공간도 사용한다. 화면 가장자리에서는 모니터 영역과 보이는 화면의 교집합 안쪽으로 8px 여백을 두고 위치를 보정한다. 높이는 해당 영역의 65% 이내로 제한하며 Safe Area·화면 크기·모바일 키보드에 따른 보이는 화면 변화를 반영한다. 패널 상단에는 원래 열의 `owner/repo`를 표시한다.
- 분할 화면 전체에서 상세 팝업은 하나만 연다. 다른 열의 커밋을 선택하면 이전 팝업·노드 강조·선택 메타데이터 대상을 해제하고 새 저장소의 상세를 표시한다. SHA가 같아도 저장소가 다르면 선택을 교체한다. 패널의 DOM과 이벤트는 원래 열에 속하므로, 열 바깥으로 나온 패널도 클릭·터치·내부 스크롤·닫기가 가능하다. 패널이 열려 있을 때만 위치를 관찰하며 위치 보정 자체는 API 요청을 만들지 않는다.
- 상세 내용만 내부에서 스크롤하며 닫기·GitHub 이동 버튼과 저장소 이름은 상단에 고정한다. 키보드·휠·터치 스크롤과 본문 하단의 메타데이터 추가 조회를 유지하며 다른 커밋을 고르면 본문을 맨 위로 되돌린다. 팝업 내부 클릭은 유지하고, 다른 열을 포함해 팝업 밖 빈 공간을 누르면 공통 선택을 해제한다. 메시지 뒤의 실제 글자가 없는 여백은 커밋 선택 영역에 포함하지 않는다.
- 상세를 닫으면 선택도 해제한다. 단일 화면으로 복귀할 때 추가 저장소의 팝업은 닫고 이후 재진입해도 자동으로 다시 열지 않는다. 현재 기본 저장소의 선택은 유지할 수 있으며 일반 화면의 기존 상세 배치로 복원한다. URL 구성에서 제외된 저장소의 선택도 해제한다.
- 각 열의 가로 표시 범위 안에서 현재 화면 하단 이전에 있는 미조회 경계에 기존 점진 로딩을 호출한다. 빠른 점프 후 응답이 도착해도 후속 경계가 여전히 화면 위쪽에 있으면 현재 화면까지 경로가 이어지도록 다음 페이지를 조회한다. 경계가 화면 아래로 이동하거나 루트·이미 읽은 합류점에 도달하면 멈춘다. 한 열의 스크롤이 다른 열을 이동시키거나 화면 아래의 이력을 미리 읽지 않으며, 기존 동시 요청·한도·오류 정책을 유지한다.
- 최신 위치의 새 커밋 추적·240ms 애니메이션·사용자 조작 시 추적 중단·과거 탐색의 SHA 앵커 보정은 기존 `scrollPosition`과 Graph 로직을 저장소마다 적용한다.
- 모니터 대상에서 제외된 기존 일반 그래프는 DOM과 상태를 보관하면서 Canvas 렌더링·보이는 커밋 조회를 멈춘다. 종료 시 원래 단일 모드 URL과 그래프로 복귀한다.

### 커밋 상세와 하단 고정 안내의 배치

- 안내가 없으면 넓은 일반 화면(800px 초과)은 그래프 오른쪽·아래쪽 16px, 좁은 화면은 기존 `70px + safe-area`, Split view는 선택 열 중앙을 기준으로 그래프 영역 바닥 8px 위에 배치한다.
- `.app-notices`에는 화면 하단에 고정되는 안내만 둔다. 현재 PWA 업데이트 안내·디버그 진입점·디버그 로드 오류가 해당하며, 이후 추가되는 하단 안내도 이 영역에 둔다. 영역 안에 표시되는 요소는 모두 하단 안내로 측정한다. 이동 가능한 디버그 패널처럼 하단 안내가 아닌 UI는 `.app-notices` 밖의 앱 루트에 렌더링해 측정 대상에서 제외한다. 안내가 있으면 화면이나 열에 관계없이 팝업을 안내 위로 올려 최소 8px 여백을 확보한다. 가로로 겹치지 않는 열에도 같은 정책을 적용한다.
- `ResizeObserver`로 실제 렌더링된 높이와 위치를 측정한다. 줄바꿈·오류 문구·동시 표시·등장·닫힘·창 크기 변경을 반영하며 고정 안내 높이를 가정하지 않는다. 일반 화면에는 CSS 변수로 전달하고, Split view는 `monitorDetailsFrame`의 하단 경계를 안내 위로 줄여 다시 계산한다. 팝업이 올라간 만큼 최대 높이도 줄여 툴바나 그래프 상단을 넘지 않게 한다.
- 안내 변화만으로 팝업을 다시 열거나 포커스를 옮기지 않고 내부 스크롤 위치를 유지한다. 안내가 사라지면 기본 배치로 돌아간다. 안내가 위에 그려지는 기존 z-index 관계는 유지하고 실제 배치로 겹침을 방지한다.

## 활성 헤더의 순서 변경

- 각 저장소 이름 왼쪽의 작은 grip 핸들에서만 드래그를 시작한다. 저장소 이름은 기존 GitHub 링크와 말줄임을 유지한다. 핸들 title은 `Drag to reorder`이며 별도 정렬 모드나 상시 안내를 추가하지 않는다. 키보드 정렬은 기존 선택 창의 ↑/↓ 기능을 사용한다.
- 마우스는 누르면 즉시, 터치는 약 400ms 동안 누른 뒤 활성화한다. 활성화 전 6px 넘는 이동은 대기를 취소하고 기본 터치 동작을 막지 않는다. 터치 제어·선택 방지·컨텍스트 메뉴 차단은 핸들에만 적용한다.
- 드래그 중 원래 헤더만 35% 불투명도, 미리보기는 95%의 떠 있는 카드로 표시한다. 카드에 grip·저장소 이름·목표 순번을 넣고 2px 테두리와 그림자로 구분한다. 마우스 포인터 옆을 따라 화면 안에서 움직이며, 터치는 공간이 있으면 손가락 24px 위에, 상단에서는 32px 아래에 표시해 가리지 않는다. 원래 열 경계에는 헤더부터 화면 하단 Safe Area까지 이어지는 3px 삽입선을 표시한다. 다른 헤더와 모든 그래프는 불투명도 100%이며 실제 배열·그래프 순서는 드롭 전까지 유지한다.
- 실제 위치가 바뀐 드롭은 이동한 헤더의 테두리·배경을 600ms 동안 강조한 뒤 복원한다. 새 드래그나 컴포넌트 종료 시 강조를 취소하며, reduced motion에서는 생략한다. 별도 타이머나 그래프 이동 애니메이션은 추가하지 않는다.
- Escape·포인터 취소·캡처 해제·blur·화면 크기 변경·세션 종료·대상 목록 교체는 확정하지 않고 취소한다. 대기 타이머·포인터 캡처·전역 리스너도 정리한다. Escape는 먼저 드래그만 취소해 현재 커밋 상세와 분할 모드를 유지한다. 같은 위치의 드롭은 URL·설정·세션을 갱신하지 않는다.
- 확정하면 기존 `moveMonitorRepository`와 `MonitorSession.reorder`로 이름 순서만 바꾼다. 저장소 식별자로 연결한 Entry·History·CommitInfoStore·Canvas·스크롤·기준 브랜치·선택 상세·진행 중 요청을 재사용한다. 갱신 범위 식별자는 저장소 집합에 기반하므로 순서 변경이 공통 타이머를 다시 시작하지 않는다.
- `useRepositoryLocation.navigate`의 replace 경로로 `repo`와 대응 `branch`를 함께 이동한다. 페이지를 새로고침하거나 history 항목을 추가하지 않는다. 이미 같은 모델·브랜치인 URL 재배열은 모델을 다시 시작하지 않으며 실제 저장소 집합·브랜치 변경은 기존 초기화 경로를 따른다.
- 공유 URL을 열기만 해서는 기존 저장 선택을 새 구성으로 덮어쓰지 않는다. 직접 드롭하거나 선택 창에서 시작을 누른 경우에만 기존 이름 배열에 순서를 저장한다. 저장 실패 시에도 현재 화면과 URL은 변경하며, 별도의 PAT·메타데이터 저장 형식은 추가하지 않는다.
- 기존 1~32개 가로 균등 분할을 유지한다. 헤더 공간 안에서 핸들을 줄이고 공통 버튼의 좌우 공간은 클리핑으로 보호한다. 극단적인 정보 밀도에서 가장자리 헤더의 조작 영역이 부족하면 기존 선택 창에서 정렬할 수 있다. 그래프 개수나 순서를 임의로 줄이지 않는다.

## 공통 갱신과 오류

- 각 열의 로딩 표시는 일반 화면과 같은 공통 컴포넌트를 사용한다. 이력·메타데이터를 포함한 해당 저장소의 실제 진행 중 HTTP 요청 수만 `xN`으로 표시하고, 다른 열의 요청 수나 대기 작업은 합산하지 않는다. 1~4개는 느리게·5~8개는 보통·9개 이상은 빠르게 회전하며 동작 줄이기 설정을 따른다. 요청이 모두 종료되면 숫자를 숨기고 후처리가 끝나면 인디케이터도 숨긴다. 완료·오류·취소 시 개수를 정리하며 API 요청·갱신 타이머·캐시 정책을 추가하거나 변경하지 않는다.

- 첫 진입의 이력·메타데이터 로딩이 끝나기 전에는 공통 새로고침 버튼을 비활성화하고 채움 타이머와 자동 갱신 예약을 시작하지 않는다. 일부 또는 전체 저장소가 실패했더라도 초기 작업이 모두 종료되면 그 시점부터 전체 갱신 주기를 시작한다. 초기 로딩 이후에는 기존 dispatch 기준 타이머와 저장소별 독립 응답 반영을 유지한다.
- 채움은 화면 반영 시 실제 예정시각에 맞춰 정렬하며 탭·온라인 복귀 시에도 다시 맞춘다. 렌더링 지연이 새 애니메이션의 시작 지연으로 누적되지 않게 하고, 자동 실행 시에는 현재 예정시각을 다시 검사한다.

- 기존 `RefreshLoop` **한 개만** 스케줄을 소유한다. 일반 설정의 자동 갱신 ON/OFF와 30초(PAT 필요)·1분·5분을 공유하며 별도 주기는 추가하지 않는다.
- 공통 시점마다 선택한 저장소의 갱신을 시작한다. 느린 작업이 끝날 때까지 타이머를 붙잡지 않고, 각 모델이 응답을 받는 대로 화면을 반영한다.
- 공통 갱신 완료 시각은 해당 주기에 새로 시작한 저장소 작업이 모두 끝난 시각이다. 일부·전체 오류도 완료로 기록하되, 진행 중인 작업이 남아 있으면 먼저 갱신하지 않는다. 이전 주기부터 진행 중이어서 이번에 건너뛴 작업은 이번 주기의 완료 대기에 넣지 않으며, 모두 건너뛰면 완료 시각을 바꾸지 않는다. 완료 추적은 다음 dispatch와 분리해 기존 주기와 단일 타이머를 유지한다. 종료·교체된 세션의 늦은 완료는 무시한다.
- 이전 갱신 작업이나 최초 로딩·기준 브랜치·방향 변경 로딩이 진행 중인 저장소는 중복 갱신을 건너뛴다. 스크롤 경계·브랜치 탐색·메타데이터 추가 조회는 갱신을 막지 않으며, 다른 저장소는 다음 공통 주기에도 갱신할 수 있다.
- 기존 SHA 커밋 캐시·ETag/304·중복 요청 공유·증분 브랜치 갱신·완료 Actions 추적 중단을 유지한다. 저장소별 HTTP 풀과 기존 재시도 처리를 사용한다.
- 비인증 자동 갱신은 일반 모드와 같은 [조회 절약 정책과 예외](auto-refresh-and-metadata.md#94-비인증-자동-갱신)를 적용한다. 변경 없는 저장소는 정보 한 건만 조회하되 최초 로딩 후 첫 갱신·Push 감지 후 후속 갱신, 미완료 Actions 추적과 실패한 메타데이터 재시도는 해당 예외를 따른다. 수동·인증 갱신은 전체 조회하며, 한도에 도달하면 토큰 필요 안내를 표시한다.
- 같은 PAT의 한도를 독립 쿼터로 취급하지 않는다. 어느 열에서든 확인한 Rate Limit 재시도 시각을 세션 전체에 즉시 적용해 갱신·추가 경계/상세 요청을 기다리게 한다. 이미 전송된 요청은 도착할 수 있다. 새 인증으로 바꾸면 이전 인증의 대기 시각과 늦은 결과는 무효화한다.
- 네트워크·권한·404·부분 메타데이터 오류는 해당 열에 표시하고 다른 열을 유지한다. 초기 메타데이터 실패는 다음 공통 주기에 다시 시도한다.
- 상단 새로고침은 실제 버튼이며 클릭·탭·키보드로 기존 `RefreshLoop.refresh()`의 수동 갱신을 실행한다. 선택한 저장소 중 이전 갱신이 진행 중이거나 최초 로딩·기준 브랜치 로딩 중인 항목은 기존 `MonitorSession.refreshAll` 정책으로 건너뛰고 나머지를 갱신한다. 스크롤 경계·브랜치 탐색·메타데이터 추가 조회가 진행 중이라는 이유로는 건너뛰지 않는다. 자동 갱신 OFF 상태에서도 수동 갱신을 사용할 수 있으며 한도 대기·갱신 디스패치 중에는 비활성화한다. 기존 SVG 원형 진행 표시와 CSS 애니메이션을 재사용하고 별도 JS 타이머를 만들지 않으며, 가운데 새로고침 문자는 회전하지 않는다. 진행 상태는 접근성 이름과 `aria-busy`로 알린다.
- 백그라운드·오프라인에서는 기존 스케줄을 멈추고, 기한이 지난 복귀는 한 번 갱신한다.
- 종료 시 추가 열의 요청·구독을 취소하고 정리한다. 일반 모드에서 계속 사용하는 현재 저장소의 작업은 유지하며, 같은 `RefreshLoop`를 단일 저장소 범위로 되돌린다.

## PWA와 측정

정적 앱 셸 캐싱과 업데이트 정책은 바꾸지 않는다. API 응답·PAT를 Service Worker로 캐시하거나 백그라운드 동기화를 추가하지 않는다. PWA의 기본 시작 주소 `/`는 일반 모드이며 저장한 선택을 다시 사용할 수 있다. 명시적 모니터 URL을 열거나 그 주소에서 새로고침하면 분할 구성을 복원한다.

기존 개발자 디버그 모드의 HTTP 종류·상태·캐시·동시 요청·갱신·DAG·Canvas 측정을 사용한다. 최근 20개 표본과 진단 복사는 기존 정책을 따르며 저장소 이름이나 선택 목록을 측정 데이터에 추가하지 않는다. Graph 요약은 마지막으로 렌더링한 그래프의 값이고, 요청·타이밍 표본은 여러 그래프에서 모인다. 디버그가 꺼져 있으면 상세 측정용 스냅샷을 만들지 않는다.

## 검증 범위와 한계

자동 테스트는 선택·32개 제한·저장·URL·순서 변경·모델 보존·공통 갱신·오류 격리·Rate Limit 공유를 검증한다. 브라우저에서는 마우스·터치·키보드 정렬, 좁은 열의 그래프와 상세, 회전·Safe Area·포커스를 별도로 확인한다.

과거 로컬 Chromium 검증은 합성 GitHub 응답과 뷰포트·터치 에뮬레이션을 사용했다. 당시 테스트 개수·합성 성능 수치는 현재 구현의 성능 보장이 아니다. 기존 상세 기록은 이 문서의 Git 이력에서 확인할 수 있다. 설치형 iOS/Android PWA의 롱 프레스·컨텍스트 메뉴·Safe Area, 실제 가상 키보드와 VoiceOver/TalkBack 낭독은 별도 실기기 검증이 필요하다.

## 알려진 제약과 제외

- 설치된 iOS/Android PWA, 실제 가상 키보드·Safe Area·저사양 기기 성능, VoiceOver/TalkBack 낭독은 실기기에서 추가 확인해야 한다. OS 상태 표시줄과 사용자가 직접 선택하는 브라우저 전체화면은 플랫폼 정책을 따른다.
- 320px 세로 화면의 4열은 열당 약 80px뿐이다. 노드·간선은 남지만 많은 레인의 간격과 이름·상세 텍스트 가독성은 제한된다. 가로 화면 또는 적은 저장소 수를 권장한다.
- 메모리와 요청량은 선택한 저장소의 수·크기·Actions 상태에 따라 증가한다. 기존 요청 풀은 저장소/리더 범위이며 관찰된 동시 요청 수가 전체 앱의 고정 상한은 아니다.
- 2×2·저장소별 주기/PAT·스크롤 동기화·강제 방향 전환·Actions 실행/취소·알림/소리·WebSocket/Webhook·서버 분석은 제외한다.

### 경로 선택 입력의 공통 정책

각 열에서도 넓은/좁은 일반 화면과 같이 브랜치 이름·라인 클릭/탭으로 상세 없이 경로를 강조한다. 노드·메시지·태그/릴리즈 아이콘 클릭/탭은 기존 상세를 연다. 각 열의 고정 강조는 독립적으로 유지한다. 배지·선은 어느 열에서 누르든 공용 상세를 닫으며, 다른 열의 배지·선 고정 강조는 지우지 않는다. 빈 공간·상세 닫기·대상 삭제는 해당 강조를 해제한다. 스와이프·취소·롱 프레스는 새 경로를 선택하지 않는다. 세부 판정과 수명은 [공통 명세](dag-hover-highlight.md#입력과-수명)를 따른다.
