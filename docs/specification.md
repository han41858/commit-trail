# Commit Trail — 개발 명세서 v0.3

> Explore the flow of Git history.

이 문서는 현재 제품의 기능과 공통 제약을 요약합니다. 문서별 역할·기능별 상세 명세·구현 근거는 [문서 안내](README.md)를 따릅니다. 초기 구현 요청이나 변경 이력 대신 현재 동작을 기술합니다.

## 1. 개요

Commit Trail은 GitHub 저장소의 커밋과 브랜치 관계를 **세로형 그래프**로 시각화하는 오픈소스 웹앱입니다. GitHub Insights → Network와 비슷한 Git DAG 뷰어이지만, 세로 스크롤과 미니멀한 인터랙션을 중심으로 설계합니다.

- 저장소: `han41858/commit-trail`
- 형태: 모바일 대응 읽기 전용 SPA
- 배포: 정적 호스팅, 자체 백엔드·데이터베이스 없음
- 핵심: 실제 커밋의 부모·자식 관계를 정확히 표시
- 범위: 조회·시각화·자동 갱신·커밋 메타데이터·Split view·PWA

## 2. 현재 기능

Monitor Mode는 기존 단일 저장소 탐색을 유지하면서 현재 앱 창을 최대 32개 저장소의 가로 한 줄로 분할한다. 일반 헤더의 분할 아이콘에서 최근 이력·직접 주소로 대상을 선택하고, 위 선택 목록의 핸들 드래그·↑/↓로 좌우 순서를 정한다. 선택된 항목은 아래 최근 목록에서 숨긴다. 공통 수동 갱신 버튼과 카운트다운·독립 스크롤·기존 Canvas/상세를 사용한다. 반복 `repo` URL 또는 한 개의 `repo`와 `mode=monitor`로 구성을 복원하며, 선택 창의 **Copy link**로 이름·순서·모드와 확인된 현재 기준 브랜치를 공유한다. 비공개 이름의 URL 노출을 안내하고 인증·디버그·갱신 설정은 공유하지 않는다. 뒤로/앞으로 가기·새로고침도 URL 구성을 따른다. 복귀 버튼 또는 Escape로 단일 모드로 돌아가며, 브라우저 전체화면은 앱이 조작하지 않고 사용자가 F11 등으로 선택한다. PAT 변경 시 비공개 선택을 정리한다. 상세 구현·검증·기기 제약은 [Monitor Mode 명세](monitor-mode.md)를 따른다.

활성 Split view의 저장소 이름 왼쪽 핸들에서 순서를 바꿀 수 있다. 마우스는 즉시, 터치는 400ms 롱 프레스 후 드래그하며, 헤더 미리보기·삽입선만 움직이다가 드롭 시에만 기존 모델·스크롤·선택·갱신을 보존해 순서와 URL/설정을 반영한다. Escape·터치 취소는 변경하지 않고 닫으며, URL은 replaceState 경로를 사용한다. 공유 URL 열기만으로 저장 선택을 덮어쓰지 않고 기존 설정 창의 키보드 정렬도 유지한다.

선택 창을 다시 열면 직전 Split view 구성 또는 저장한 선택의 항목·순서를 그대로 복원한다. 제거한 현재 저장소를 자동으로 다시 추가하지 않으며, 기존 구성이 없는 최초 선택에만 현재 저장소를 기본값으로 사용한다.

### 2.1 저장소 입력
- `https://github.com/owner/repo`, `owner/repo` 입력 지원
- 입력창은 소문자만 받는다. 입력·붙여넣기·URL `repo` 초기값을 소문자로 바꾸고 모바일 자동 대문자화·자동 수정·맞춤법 검사를 끈다. 중간에 대문자를 입력하거나 선택 영역을 바꿔도 커서·선택 위치를 유지한다. GitHub는 저장소 경로를 대소문자 구분 없이 처리하므로 조회 결과는 같다
- 주소 입력창 오른쪽 지우기 버튼은 입력 내용만 비우고 다시 입력할 수 있게 포커스를 유지하며 조회 중인 그래프는 유지
- URL에 저장소가 지정되지 않으면 입력창을 비우고 자동 조회하지 않음. 빈 화면의 데모 버튼은 `han41858/commit-trail`을 중립 색상·점선 밑줄로 안내하고 외부 이동 화살표는 표시하지 않음. 누르면 주소 입력창에 반영하고 조회
- 단일 뷰의 최초 조회·저장소 전환에서 아직 커밋이 없고 조회 중이면 중앙 제목을 `Loading...`으로 표시. 조회 전 첫 화면의 `Watch your Git history unfold.` 슬로건과 기존 로고는 유지하며, 하단 로딩 인디케이터는 그대로 사용
- 저장소 메타데이터, 기본 브랜치 및 브랜치 참조 조회
- 저장소 식별자와 명시적인 기준 브랜치를 URL에 반영하여 링크 공유 및 새로고침 후 복원
- 성공한 메타데이터의 공개 여부와 방문 시각을 사용해 최근 저장소 10개를 브라우저에 저장. 입력 포커스 시 로컬 자동완성·방향키/Enter 선택·개별 삭제·Clear history를 제공하며, 현재 저장소 추천 재선택은 API 재조회와 그래프 초기화를 생략. PAT 변경·삭제 시 비공개 이력만 제거하고 동일 토큰·복원은 유지. 저장소 오류 시 이 기능만 비활성화. 상세 정책은 [최근 방문 저장소 명세](recent-repositories.md)를 따른다
- 잘못된 주소, 미존재·비공개 저장소, 네트워크 오류 안내

### 2.2 공개·비공개 저장소
- Public: 별도 인증 없이 GitHub REST API 사용
- Private: 사용자가 직접 입력하는 **fine-grained PAT**로 조회
- 토큰 패널에서 토큰 유무에 따른 API 한도(IP당 시간당 약 60회 / 약 5,000회)를 짧게 안내
- PAT 발급 안내: Actions 모니터링에는 선택적으로 `Actions: Read-only` 권한을 추가하며 권한 부족 시 그래프는 유지.
- PAT 발급 안내: 저장소 선택 및 `Contents: Read-only` 권한; PR 추천 집계에는 `Pull requests: Read-only`도 필요
- 토큰 팝업은 기능·필요 권한·접근 상태를 표로 표시. 적용한 토큰의 인증과 현재 저장소의 Contents·Pull requests·Actions 접근을 확인하며 재확인 제공. 접근 가능은 ✅, 접근 차단·만료는 🚫로 표시하고 요청 제한·확인 실패는 별도 상태로 구분. 로그인 ID·Access to·반복되는 Public repository 문구는 생략하고 토큰 생성 링크는 눈에 띄는 버튼으로 표시. 추가 정보 아이콘과 중첩 설명 팝업은 제공하지 않음
- 토큰·설정·브랜치·커밋 상세 팝업은 바깥 누르기와 Escape로 닫고, 내부 입력과 버튼 조작은 유지. API 제한 안내에서 토큰 팝업을 열면 이전 안내는 닫되 재시도 제한은 유지하며, GitHub 토큰 발급 링크를 열 때도 토큰 팝업을 닫음
- 적용한 토큰은 브라우저 localStorage에 저장하고 새로고침 시 자동 복원. 삭제 시 저장된 토큰과 화면의 이력을 함께 제거하며 저장소 접근 오류는 토큰 패널에 표시
- 저장된 토큰 보호를 위해 CSP로 스크립트는 같은 출처에서만 실행하고 GitHub API 요청은 `api.github.com`으로 제한하고 PWA 정적 자산 요청은 같은 출처에서만 허용
- 토큰을 URL, sessionStorage, IndexedDB, 로그, 분석 서비스에 저장하거나 노출하지 않음
- 인증 토큰은 GitHub API 요청에만 사용
- 토큰이 잘못되었거나 접근 권한이 없을 때 안내
- GitHub 계정 로그인·OAuth·GitHub App은 현재 범위에서 제외

### 2.3 세로형 커밋 그래프
- 커밋을 작은 원형 노드, 부모 관계를 선으로 표시
- 브랜치 분기와 Merge Commit의 다중 부모 관계 표시
- 하나의 SHA를 그래프에서 중복 노드로 표시하지 않음
- 색상과 하이라이트는 공통 경로 ID를 사용. 첫 번째 부모선은 자식 경로, 두 번째 이후 부모선은 유입 경로에 속하며, 중간 참조나 동일 색상 때문에 경로를 나누거나 합치지 않음. **브랜치 참조·경로·배치 레인은 서로 다른 개념임**
- 경로 소유권은 선택한 기준 HEAD → 저장소 기본 HEAD를 첫 부모 자식 여부와 관계없이 먼저 고정. 기본 HEAD가 기준 경로에 포함되면 기준 소유권을 유지. 나머지 일반 참조는 로딩된 첫 부모 자식이 없는 HEAD만 자기 고유 첫 부모 줄기의 통합 근거 → 위상상 가장 오래된 고유 커밋의 `commitTime()` 오름차순 → HEAD SHA 순으로 처리한 뒤 이름 없는 경로를 배정. 중간 참조는 별칭이며 두 번째 이후 부모 병합은 끝점을 제외하지 않음. 물려받은 공통 병합·중복 부모·확인된 기준/기본 브랜치 동기화는 통합 근거에서 제외. 이름·HEAD 최신 시각을 특별 취급하지 않음. 첫 커밋은 전체 이력의 최소 timestamp가 아니며 유효한 커미터 시각 → 작성자 시각을 사용하고 모두 미상이면 알려진 시각 뒤·SHA 순서로 처리. Rebase·시각 오류·부분 이력으로 첫 커밋과 순서가 바뀔 수 있고 실제 생성·통합 의도를 확정하지 못함
- 8색 팔레트에서 기준 경로는 0번, 나머지는 HEAD 참조의 전체 브랜치 이름(HEAD에 이름이 없으면 SHA) 해시를 기본으로 사용. 중간 참조는 경로를 나누거나 이름 해시의 기준이 되지 않음. 기준 경로 우선·각 경로가 소유한 가장 오래된 로딩 커밋 SHA 순서(동률은 HEAD SHA)로 인접 충돌을 보정하며 8색을 모두 피할 수 없으면 최소 충돌 후보를 결정적으로 선택
- localStorage·이전 색 배정 없이 계산해 같은 참조·로딩 범위·기준 브랜치와 HEAD SHA·저장소 기본 브랜치 정보이면 브라우저·입력 도착 순서와 관계없이 같은 색을 표시. 화면 너비·방향·테마 변경은 팔레트 번호를 바꾸지 않음. 새 참조·과거 이력으로 경로 경계나 이웃이 바뀌면 충돌 보정 결과와 색상이 달라질 수 있음
- 텍스트를 최소화해 노드 및 선 관계에 집중
- 데스크탑 브랜치 영역은 실제 레인 수에 필요한 너비만 사용하며 최대 화면 너비의 50%로 제한. 메시지·SHA·작성자는 바로 옆에서 시작하고 각각의 표시 너비를 최대 50%로 제한. 긴 텍스트는 말줄임하고 상세에서 전체 내용 확인
- 그래프 방향: **최신 → 과거(기본)** / **과거 → 최신** 전환
- Git DAG의 위상 순서를 보존하고, 커밋 날짜만으로 부모·자식 순서를 결정하지 않음. 위상상 표시 가능한 커밋 중 커미터 시각(없으면 작성 시각)이 최신인 것을 우선해 오래된 브랜치 HEAD가 최근 이력 사이에 끼지 않도록 함
- 시간 방향 변경 시 선택한 브랜치의 최신/가장 오래된 이력에서 다시 시작하며, 화면을 아래로 스크롤해 선택한 방향으로 이어서 탐색

### 2.4 커밋 인터랙션
- 노드·메시지·태그/릴리즈 아이콘 클릭·탭으로 커밋 상세와 선택 강조를 표시. 노드·메시지 Hover는 해당 경로를 강조하고 기존 툴팁을 표시하며, 태그/릴리즈 아이콘 Hover는 기존 툴팁을 표시. Hover만으로 커밋을 선택하거나 상세를 조회하지 않음
- SHA(축약), 메시지, 작성자, 날짜, GitHub 원본 링크
- 커밋 선택 상태 유지 및 원본 커밋 페이지로 이동
- 아직 조회하지 않은 이력이나 불완전한 관계는 완전한 데이터처럼 표현하지 않음

### 2.5 브랜치
- `main` → `master` → 저장소 기본 브랜치를 목록 앞에 고정하고 중복 이름은 한 번만 표시
- 초기 기준 브랜치는 URL의 `branch` → 저장소별 마지막 직접 선택 → `main` → `master` → GitHub 기본 브랜치 → 기존 대체 정책 순서로 결정. 선택 이후에는 우선순위를 재적용하지 않고 추천 목록 순서는 그대로 유지
- 직접 브랜치를 바꿀 때만 저장소별 기록을 남기고 URL의 `branch`도 갱신. 자동 선택·URL 복원·자동 갱신은 기록을 덮어쓰지 않음. 부분 목록에 없는 후보는 기존 정확한 이름 조회로 확인하고 확인된 삭제만 정리. 네트워크·권한·Rate Limit 오류는 기록과 기존 그래프를 유지
- 단일 화면과 Split view에 같은 초기 선택 정책을 적용. 반복 `branch`는 반복 `repo` 인덱스와 대응하며 중간 누락은 빈 값으로 보존. 브랜치 대소문자·표준 URL 인코딩을 유지하고 뒤로/앞으로 및 새로고침으로 복원
- 추천은 우선 브랜치를 포함해 최대 30개, 나머지는 최근 90일간 병합 PR의 대상 횟수 순
- 추천 목록을 열 때 PR을 소규모로 집계하고 부분 집계 상태와 이어서 집계할 수 있는 버튼 제공
- 현재 존재하는 브랜치만 추천하고, 목록 밖의 브랜치는 검색 및 정확한 이름 조회로 선택 가능
- 기본 브랜치 및 조회 가능한 브랜치 HEAD 표시
- 기준 브랜치를 선택하며 그 HEAD의 첫 번째 부모를 따라가는 경로는 직선 레인에 고정
- 다른 브랜치 및 병합된 이력은 별도 레인에 배치하고 실제 부모 SHA 관계로만 연결
- 공통 조상이 조회되지 않거나 관련 없는 이력은 임의로 기준선에 연결하지 않음
- 스크롤 중 보이는 브랜치 경로 가까이에 이름을 유지하고 경로가 화면을 벗어나면 숨김
- 머지 연결선과 화면을 가로지르는 곡선도 이름 표시 대상이며, 가까운 이름 배지는 겹치지 않게 배치
- 기준 브랜치 묶음의 우선순위는 유지하고, 나머지는 긴 이름의 공간을 먼저 확보한다. 기존 배지의 가장자리도 대체 위치로 검토하며, 노드를 피할 공간이 없는 경우에도 가까운 범위에서 이름끼리 분리하는 배치를 우선한다. 이름을 숨기거나 경로에서 멀리 이동시키지 않는다.
- 이름은 구분 가능한 가장 짧은 경로 접미사로 간략화하고, 폭이 부족하면 남은 이름의 앞부분을 유지하며 뒤쪽을 `…`로 생략. 같은 커밋의 참조는 기준 브랜치를 맨 위에 두고 나머지를 이름순으로 정렬해 개별 배지를 세로로 나열하며, `+N`으로 이름을 숨기지 않음. 배지 묶음의 전체 높이로 주변 배지와 충돌을 피하고 커밋 좌표·레인·행 간격은 유지. 화면보다 큰 묶음은 HEAD에 고정하고 스크롤 영역을 확보해 모든 이름을 확인할 수 있게 함. 외곽선 대신 경로 색상을 은은하게 채운 배지를 사용하며 전체 이름은 데스크톱 Hover와 브랜치 선택 메뉴에서 확인
- 배지는 노드와 선택 상태를 포함한 Actions 링 주변에 여백을 확보하고 같은 높이의 가까운 공간부터 찾음. 너비 계산에도 선택 링의 반지름 12px과 간격 3px을 반영해 좁은 화면에서는 이름을 조금 더 축약하고 원래 경로 옆에 배치. 짧은 경로의 대체 배치는 원래 위치에서 커밋 한 행(31px) 이내로 제한해 무관한 과거 커밋 옆으로 밀리지 않게 함. 오른쪽 배치에서 가려지는 노드가 있으면 오른쪽 여유 공간을 활용하고, 공간이 없으면 왼쪽이나 다른 높이로 이동. 배경은 약 40% 불투명도로 그리고 글자는 선명하게 유지하며, 좁은 화면에서 겹침이 남더라도 노드·링의 클릭과 Hover가 배지에 막히지 않음
- 다른 브랜치의 고유 경로 이름은 다른 경로 합류 지점까지 표시. 처음부터 기준선에 있는 참조는 보이는 공통 이력에서 함께 표시
- 여러 브랜치가 같은 커밋을 가리킬 수 있음
- 브랜치가 삭제되면 참조 이름이 남지 않을 수 있으므로 복원 가능하다고 가정하지 않음

### 2.6 반응형
- 데스크톱: 세로 스크롤, Hover 경로 하이라이트와 기존 툴팁, 클릭으로 상세 팝업 표시
- 브랜치 배지가 말줄임되거나 경로 접두사가 생략된 경우에만 Hover 또는 탭으로 전체 이름을 별도 지연 없이 표시. 전체 이름이 그대로 보이는 배지는 툴팁을 표시하지 않음. 긴 이름은 줄바꿈하고 툴팁을 화면 안에 배치하며, 배지를 벗어나거나 스크롤·클릭·Escape·화면 변경 시 닫음. 일반·Split view에서 같은 동작을 사용하고 터치의 기존 선택 동작과 커밋·Actions의 기본 툴팁은 유지
- 모바일: 그래프 너비를 화면 100%로 고정하고 브랜치 수에 따라 레인 간격을 압축. 메시지 영역을 확보한 실제 레인 간격이 12px 이상이면 브랜치 영역을 최대 50%로 제한하고 옆에 최대 화면 너비 50%의 한 줄 커밋 메시지를 표시. 12px를 확보하지 못하면 메시지를 숨기고 그래프에 전체 화면 너비를 사용. 모든 브랜치를 화면 안에 표시하며 세로 스와이프와 노드·메시지 Tap 상세 정보 지원
- 터치 대상 영역은 실제 노드보다 넉넉하게 구성
- 모바일의 필수 동작은 Hover에 의존하지 않음. 브랜치 배지·커밋 노드·보이는 메시지의 Hover와 커밋 노드·메시지의 클릭·탭은 화면 너비·일반/Split view에 관계없이 해당 흐름 전체와 시작·종료 경계를 강조하고, 양쪽 경계 너머의 공통·병합 이력은 흐리게 표시. 현재 조회된 데이터만 사용하며 선택 해제 시 강조도 해제
- 밝은/어두운 테마, 시스템 설정 기본

## 3. UI 원칙

- 브랜치 배지·노드·보이는 메시지 Hover와 커밋 클릭·탭은 공통 경로 ID로 흐름의 시작·종료 경계를 강조한다. 병합선은 유입 부모부터 경로 시작 경계와 선택한 병합점까지 표시한다. 배지·라인 클릭·탭은 공용 상세를 닫고 경로를 고정 강조한다. 열별 강조는 독립적으로 유지하며, Hover는 상세를 유지한 채 임시 우선한다. 잘린 배지 탭은 전체 이름도 표시하고 터치 연결선은 12px, 마우스는 5px로 판정한다. 빈 공간·상세 닫기·대상 삭제는 관련 선택을 해제하고 유효한 대상은 크기·열 순서 변경에도 유지한다.
- 비대상 노드·메시지·연결선·배지·Actions·태그/릴리즈 아이콘은 기존 불투명도의 25%로 표시하고 140ms 동안 전환한다. 각 Split view 열은 독립적이며 상세 정보·상태 색상·진행률은 유지한다.
- 경로 소유권·색상 충돌 보정·종료 판정의 한계, 5px 곡선 판정·100ms 빈틈 유지·전환 수명과 성능 조건은 [공통 경로 색상·하이라이트 명세](dag-hover-highlight.md)를 따른다. API 요청·새 설정을 추가하지 않는다.
- 저장소 입력과 그래프를 중심으로 단순하게 구성. 헤더 배경·테두리·그림자를 제거하고, 데스크톱 주소 입력 영역 폭은 220px, 실행은 접근성 이름이 있는 돋보기 버튼
- 그래프를 전체 뷰포트에 표시하고 저장소·기준 브랜치·방향 컨트롤은 작은 오버레이로 제공
- 상세 정보는 노드 선택 시 여닫을 수 있는 패널로 표시. 설정 메뉴에는 테마와 공통 자동 갱신 설정을 제공하며 상세 패널 버튼은 두지 않음. 해시와 오른쪽 정렬 authored 시각을 같은 줄에 배치하고, 제목 뒤에 작성자를 작은 회색 글씨의 `by 이름`으로 붙이고 본문을 표시. 필드명·부모 정보·커밋 선택 셀렉트는 제거하고 GitHub 아이콘 링크를 닫기 버튼 옆에 배치
- 모바일 하단 커밋 수·로딩 상태 영역은 화면 전체 너비 대신 내용에 필요한 너비만 사용
- 일반·Split view 모두 커밋 수 앞의 장식용 점은 표시하지 않으며, 실제 조회 중에는 기존 로딩 인디케이터를 표시
- 설정 메뉴 하단에 현재 실행 중인 앱의 빌드 시각을 작은 회색 글씨로 오른쪽 정렬한다. `Built at` 접두어를 붙여 현재 시각과 구분하고 현지 날짜와 시각을 한 줄로 표시한다. Vite 빌드 시 한 번 생성한 UTC 시각을 앱 번들에 포함하고, 앱 실행 시 브라우저의 기본 언어·지역 형식과 시간대를 사용해 연·월·일과 시·분까지만 간략하게 표시한다. 초와 GMT 등의 시간대 이름은 표시하지 않는다. 일자는 브라우저의 로캘 형식을 따르고, 시간은 현지 시간대의 24시간제 `HH:mm`으로 통일한다. 시·분은 0~9 숫자로 두 자리씩 표시하고 자정은 `00:00`이며 오전·오후 표시는 생략한다. `<time dateTime>`에는 동일한 원본 UTC 값을 유지하고 메뉴 폭은 내용에 맞추되 Safe Area와 화면 여백 안으로 제한한다. 줄바꿈하지 않으며 극단적으로 긴 형식은 말줄임하고 time 요소의 title에 전체 현지 시각을 유지한다. 현재 시각·접속 시각·GitHub 릴리즈 생성 시각과 구분하며 개발 서버는 `Development`로 표시한다. 추가 API 요청·타이머·저장소를 사용하지 않으며, PWA는 캐시된 이전 빌드로 실행 중이면 이전 빌드 시각을 유지하고 업데이트 적용 후 새 시각을 표시한다. 같은 커밋도 재빌드하면 빌드 시각과 번들 해시가 달라져 PWA 업데이트 대상이 될 수 있다.
- 모바일 그래프는 DAG 가독성을 우선하며 실제 레인 간격에 따라 메시지 표시를 자동 결정. 메시지 공간을 확보해도 레인 간격이 최소 12px이면 12px 한 줄 메시지를 최대 화면 너비 50% 안에서 말줄임하고 탭해 전체 상세를 확인. 간격이 부족하면 메시지와 메시지 탭 영역을 숨기고 브랜치에 전체 너비를 사용하며 노드 탭 상세는 유지. 수동 토글·설정은 추가하지 않고 화면 폭에 따른 배치 전환 자체는 GitHub API를 호출하지 않음. SHA·작성자는 상세 패널에서 표시
- 데스크톱 커밋 제목과 SHA·작성자 정보는 한 그룹으로 묶어 표시. 31px 커밋 간격 안에서 같은 커밋의 두 줄이 인접 커밋의 정보 줄보다 가깝게 배치
- 브랜치 선택은 모바일·데스크톱 모두 선택 전 `Branch`, 선택 후에는 `main` 같은 실제 브랜치 이름만 표시하고 시간 방향 전환과 함께 간결한 컨트롤로 제공
- 시간 방향은 상단의 `↓ Older` / `↓ Newer` 토글로 표시하고 화살표는 아래로 고정. 툴팁·접근성 이름으로도 현재 방향 안내하고, 로딩은 문구 대신 인디케이터로 표시
- 일반 화면과 Split view는 공통 로딩 인디케이터를 사용하고 실제 진행 중인 GitHub 요청 수를 `x5`처럼 표시. 일반 화면은 전체 요청 수, Split view 각 열은 해당 저장소의 요청 수를 사용한다. 대기 중인 요청은 제외하고, 1~4개는 느리게·5~8개는 보통·9개 이상은 빠르게 회전. 요청 수가 0이면 숫자는 숨기며 후처리 중에는 인디케이터만 유지할 수 있다. 동작 줄이기 설정에서는 회전을 멈추고 개수는 유지
- 월 구분선은 커미터 시각(없으면 작성 시각)을 브라우저 현지 시간대로 해석한 연·월로 묶고, 해당 월의 **로딩된 전체 커밋 중 시각이 가장 이른 커밋**에 표시한다. 병합된 분기 커밋도 후보에 포함하며 기준 브랜치의 병합 커밋에만 한정하지 않는다. 옅은 가로선은 화면 너비 전체를 지나고 오른쪽 선 바로 위에 `YYYY.MM`을 표시한다. 같은 시각의 후보는 SHA로 안정적으로 선택한다.
- 월초를 확인했는지는 기준 브랜치의 조회된 first-parent 이력으로 판단하고, HEAD 미조회 구간은 현재 조회된 연결 이력을 사용한다. 가장 오래된 부분 월은 계속 유예하며 무관한 오래된 분기가 있다는 이유로 확정하지 않는다. 더 이른 분기 커밋이 추가 로딩되면 확인된 월의 선도 그 커밋으로 옮긴다. `Older`와 `Newer`는 같은 커밋을 가리키며 표시 위치가 그래프 방향에 맞춰 반전된다. 날짜 역전에도 월별 중복 없이 Git 위상 순서와 커밋 간격을 유지한다. 일반·분할 화면 모두 같은 기준을 사용하고, 커밋 없는 월의 선이나 확인용 API 요청은 추가하지 않는다.
- 과거 이력 스크롤 안내 문구는 표시하지 않음
- 우주·궤도 이미지는 점과 선의 시각적 느낌에만 은은히 반영
- 과도한 애니메이션, 배경 파티클, 3D 효과 등 장식 배제

## 5. 데이터 처리 및 정확성

### 5.1 모델
- Commit: SHA, 부모 SHA 목록, 메시지, 작성자, 작성·커밋 일시, GitHub URL
- Branch: 이름과 HEAD SHA 참조(`name`, `commit.sha`). 저장소 기본 브랜치 이름은 별도 `HistorySnapshot.meta.default_branch`로 관리
- 커밋은 SHA를 기준으로 중복 제거하고, 브랜치는 커밋을 가리키는 참조로 취급

### 5.2 API 및 로딩
- GitHub REST API의 페이지네이션을 사용하고 요청당 최대 100개 커밋 조회
- 선택한 기준 브랜치에서 시작하고, 이름순 브랜치 HEAD 자동 조회·순회는 하지 않음
- 최신순은 화면에서 만난 미조회 부모 SHA부터 조상 이력을 조회. 머지의 모든 부모를 따라가며 참조가 삭제된 분기도 실제 SHA 관계로 확장
- 오래된 순은 첫 응답의 마지막 페이지 링크로 가장 오래된 페이지에서 시작하고, 고정된 HEAD SHA 아래 페이지 번호를 줄이며 최신 방향으로 조회. 전체 페이지 선행 다운로드 금지
- 선택한 브랜치와 최근 push·PR 머지·머지 큐 활동으로 발견한 독립 브랜치를 탐색하며 저장소 전체 이력이라고 표현하지 않음
- 최근 1년 push·PR 머지·머지 큐 활동을 시간 역순으로 읽고 기준 이력의 현재 날짜 구간에 맞는 브랜치 HEAD를 자동 확장. 이름순 브랜치 목록으로 이력을 선택하지 않음
- 활동 API는 `Link`의 `after` 커서로 이어서 조회하며, 반복·누락 커서는 자동 재시도를 차단. 활동 메타데이터는 배치당 1페이지, 독립 이력은 최대 3개. 중복 HEAD·공유 조상과 현재 날짜 구간 밖의 오래된 이력은 제외
- 오래된 순은 기준 이력이 현재 시점에 도달한 뒤 최근 독립 브랜치를 추가. 활동 이력이 없는 휴면 브랜치는 직접 선택해 탐색
- 활동 조회 오류는 기준 이력을 유지하고 자동 재시도를 멈추며 별도 재시도 제공. 현재 날짜 구간에서 비어 있던 브랜치는 구간이 과거로 확장되면 다시 검사
- API 중복 요청 최소화, 요청 취소, 오류 시 재시도 지원
- 비인증 호출의 낮은 API 제한과 인증 호출 제한을 고려
- 초기 전체 이력을 다운로드하지 않음
- 가로 표시 범위 안의 레인 중 현재 화면 하단 이전에 있는 미완료 경계를 대상으로, 실제 부모 SHA 또는 탐색 방향의 다음 이력 페이지를 자동 로딩. 화면 위쪽의 경계도 현재 화면까지의 경로를 연결하는 데 필요하므로 포함
- 가장 긴 브랜치나 전체 그래프의 끝을 기다리지 않으며, 실제 루트·이미 조회한 합류는 로딩 조건에서 제외
- 브랜치 참조 목록은 선택·이름 표시용이며, 목록 추가 조회는 커밋 조회를 유발하지 않음
- 커밋 HTTP 요청은 각 `History` 인스턴스의 커밋 요청 풀에서 최대 16개까지 병렬 처리하며, 분기별 결과는 완료되는 즉시 반영. 분할 모드의 저장소마다 독립적인 풀을 사용하고 메타데이터 조회도 별도로 동작하므로, 16개는 앱 전체 HTTP 요청 수의 상한이 아님
- 로딩 중에도 대상이 된 미조회 경계를 대기열에 추가하고, 이미 등록한 작업은 화면 밖으로 나가도 실제 부모 커밋 수신까지 유지
- Older·Newer 모두 직전 스크롤 위치를 추적하지 않고 현재 화면 하단을 기준으로 판정. End·Home·큰 점프 후에도 이 기준을 적용하며, 현재 화면 아래쪽이나 가로 표시 범위 밖의 경계는 시작하지 않음
- 병렬 응답으로 행이 삽입·재배치되면 새 좌표에서 다시 판정. 후속 경계가 여전히 화면 위쪽에 있으면 다음 페이지를 이어 읽고, 현재 화면 아래로 이동하거나 루트·이미 로딩된 합류점에 도달하면 해당 경로의 추가 요청을 멈춤
- 기존의 '새로 삽입된 화면 밖 행은 조회하지 않음' 정책을 현재 화면까지의 경로 연결에 맞춰 변경. 위쪽의 새 경계는 포함하지만 과거 최대 스크롤 구간을 누적하거나 화면 아래를 미리 읽지는 않음. 필요한 경로·페이지 수를 임의로 잘라 이력을 누락시키지 않으며, 기존 동시 요청 풀과 한도·오류 시 일시 중지/재시도 정책을 적용. 최신 추적 애니메이션 중에는 조회를 중지하고 도착한 화면에서 다시 판정
- 빈 응답이나 요청 SHA가 없는 응답은 경계 완료로 처리하지 않고 재시도 가능한 오류로 표시
- 미조회 부모는 현재 커밋 데이터의 존재 여부로 판단. 브랜치 삭제 후 정리된 부모가 병합 경로에서 다시 필요하면 경계로 복원하고 유효한 SHA 고정 페이지 캐시를 재사용. 과거에 조회했다는 이유만으로 누락된 부모의 로딩을 막지 않음
- 브랜치 정리로 사라진 부모 경계의 늦은 응답은 캐시만 재사용 가능하게 두고 그래프에 다시 합치지 않음. 해당 경계만의 오류는 무시하되 인증 실패·Rate Limit 오류는 계속 보고
- 날짜 필터 없는 고정 SHA의 첫 페이지는 요청 커밋 포함 여부를 확인한 뒤 캐시. 빈 응답·잘못된 SHA 응답은 캐시하지 않아 재시도로 복구하며, 날짜 필터가 있는 탐색·오래된 순의 후속 페이지에는 HEAD 포함을 강제하지 않음
- 동일한 미완료 경계와 동일 커밋 요청은 중복 실행하지 않음. 저장소·방향·토큰 변경 시 대기·진행 요청 모두 취소
- 경계 요청은 실행 전에 대기열에 등록하고, 완료 후 제거한 상태를 그래프에 알림. 같은 활동 커서가 여전히 미완료이고 경계가 현재 화면 안에 있다면 재검사해 다음 조회를 이어감
- 병렬 요청 일부가 실패해도 다른 결과를 유지하며 실패한 경계만 재시도
- 조회 종료 시 자동 로딩을 멈추며, 오류 시 재시도 전까지 자동 요청을 중단
- 아직 조회되지 않은 부모·분기 경계는 시각적으로 구분
- 새 데이터가 합쳐져도 기존 노드의 불필요한 레인 이동 최소화
- 새 브랜치 참조나 조상이 도착하면 저장 상태 없이 경로·인접 관계·색상을 다시 계산. 같은 최종 스냅샷은 기존 탭과 새 브라우저에서 같아야 하며, 이웃이나 경계가 바뀌었을 때의 재배정은 허용. 이전 배정을 유지해 두 브라우저의 결과를 다르게 만들지 않음
- 새 데이터가 보고 있는 위치보다 앞쪽에 삽입되어도(과거 → 최신 방향에서 과거 이력을 추가로 불러올 때 등) 화면에 보이던 커밋의 위치를 유지

### 5.3 렌더링과 성능
- Canvas 2D로 현재 뷰포트와 소량의 여유 영역만 렌더링
- 가상 스크롤/점진적 로딩으로 대량의 DOM·노드 생성 회피
- 스크롤·선택·크기 변경 등 필요한 시점에 다시 그리기
- devicePixelRatio 반영
- 메모리 캐시 우선, 영속 캐시는 필요성이 확인될 때 검토
- `angular/angular` 같은 대형 공개 저장소로 성능 검증
- 커밋 1천/1만/10만 개 수준의 합성 데이터 테스트를 단계적으로 고려하되, 조회·렌더링 한계는 실측해 결정

### 5.4 DAG 레이아웃
- 부모 SHA 관계를 정확하게 연결
- 다중 부모 Merge Commit과 공유 커밋 처리
- 선 교차, 불필요한 좌우 폭, 레인 급변 최소화
- 커밋 timestamp만으로 정렬하면 시계 오차 등으로 자식이 부모보다 과거 쪽에 놓일 수 있으므로, 부모 SHA 관계에 따른 위상 순서로 배치
- 부분 데이터가 추가될 때의 레이아웃 안정성을 고려

## 6. 오류와 빈 상태

- 잘못된 입력
- 없는 저장소 / 비공개 또는 권한 부족
- 잘못된 PAT
- API rate limit: 권한 오류와 구분하고 초기화 시각 안내 및 이른 재시도 방지
- 네트워크 장애 및 일부 요청 실패
- 빈 저장소 / 커밋 없음
- 일부 브랜치 또는 부모 커밋 미조회

오류는 이해 가능한 메시지로 표시하고, 토큰과 민감한 응답 내용은 노출하지 않습니다.

## 12. 자동 갱신 및 커밋 메타데이터 확장

세부 요구사항은 [자동 갱신 및 메타데이터 명세](auto-refresh-and-metadata.md)를 따릅니다. 기존 읽기 전용 DAG와 Canvas 2D를 유지합니다.

- 단일 공통 Polling: 인증 기본 1분, 비인증 기본 5분. 인증 시 30초 선택 가능, 1분·5분 및 ON/OFF, 수동 갱신과 마지막 시도 완료 시각 제공. 성공 여부·오류·재시도는 완료 시각과 별도 관리.
- 일반 모드는 이력·메타데이터가 모두 종료되면 성공·실패와 관계없이 완료 시각 기록. Split view는 해당 주기에 새로 시작한 저장소 작업의 마지막 종료 시각을 기록하고, 이전부터 진행 중이라 건너뛴 작업은 제외. 새 작업이 없으면 시각 유지. 이전 모드·폐기된 세션의 늦은 완료는 무시하며 기존 dispatch 주기·타이머·API·캐시 정책 유지.
- 숨긴 탭·오프라인에서는 중지하고, 복귀 시 기존 실행 예정 시각이 지났으면 갱신. 중복 실행 방지, 수동 완료 시 다음 주기 재계산, Rate Limit 기한까지 중지.
- 전체 브랜치 목록 확인 전 삭제 판단 금지. 바뀐 HEAD만 증분 조회하며 삭제된 참조의 HEAD 추적은 종료. 살아 있는 참조의 공통 조상을 모르면 캐시를 보존하되, 삭제된 참조만의 로딩된 경로는 다른 미조회 HEAD가 있어도 정리. 공유 조상·실제 머지 부모·유지되는 참조의 직전 HEAD 이력은 보호하며 SHA 페이지 캐시는 유지.
- 완전한 목록을 반영한 뒤에는 이전 활동·추천·이름 조회·추가 브랜치 페이지의 늦은 응답으로 삭제된 참조나 변경 전 HEAD를 복원하지 않음. 이전 목록의 페이지 탐색도 종료.
- 날짜 필터 없는 새 HEAD의 첫 페이지에 해당 커밋이 없으면 기존 그래프·참조·HEAD를 유지하고 오류 표시. 갱신 성공으로 확정하지 않아 다음 갱신에서 재조회 가능.
- 갱신 전 위치로 최신 이력 관찰 여부를 판단하고 최신순 상단·오래된순 하단을 따라감. 과거 탐색은 기존 커밋 위치와 선택 상태 유지.
- 🏷️ 태그·🚀 GitHub Release는 SHA로 연결하며 커밋당 버전 아이콘은 최대 하나. Release가 하나 이상 있으면 태그 수와 관계없이 🚀만, Release 없이 태그만 있으면 🏷️만 표시하고 둘 다 없으면 생략. 일반·Split view와 모바일·데스크톱에 동일하게 적용하며, 클릭·Tap 시 상세에서 모든 태그·Release 이름과 링크·연결 태그를 유지. 조회 API·데이터 구조·캐시·자동 갱신은 변경하지 않으며 추가 요청 없음. Release는 실제 Deployment 상태가 아님.
- Actions는 head_sha 일치만 연결, run_id와 최신 run_attempt로 중복 제거. 진행 중 실행의 현재 확인된 전체 Job 수로 완료율 계산; 불완전한 Job 목록에는 퍼센트 생략.
- 커밋 Actions 링은 모든 실행이 `completed`이고 최소 하나가 `success`이며 나머지가 `success` 또는 `skipped`이면 초록으로 표시. 실행·대기가 남아 있으면 기존 진행·대기 상태를 최우선으로 유지하고, 그다음 `failure`·`timed_out`·`startup_failure`는 빨강으로 표시. 전체 취소는 기존 취소 상태이며, 전체 건너뜀과 성공에 중립·취소·조치 필요·오래된 결과·미확정 결과가 섞인 경우는 회색 집계. 일반·Split view에 같은 규칙을 적용하고 원본 conclusion·상세 아이콘·Job 완료/전체 개수·진행률·조회·캐시는 유지. 보라색 기타 상태는 사용하지 않음.
- 완료된 실행은 최종 상태·Job 캐시 재사용. 최근 실행 목록에서 재실행이 확인되면 추적 재개. 불변 태그 객체는 캐시하고 목록은 ETag 조건부 조회.
- 메타데이터 변경은 DAG 배열·레인·스크롤과 분리. 실패·미완료 페이지를 삭제나 데이터 부재로 판단하지 않음.
- 토큰 저장은 사용자가 확인한 기존 localStorage 정책을 유지하며 Actions 읽기 권한은 선택 사항.
- Actions 상태는 모두 배경 없는 16px SVG 아이콘 사용. 성공은 초록 체크, 진행은 노란 회전 링, 대기는 회색 시계, 실패·시간 초과·시작 실패는 빨간색으로 구분하고 상태별 접근성 이름 유지. 이름·개수·아이콘은 세로 중앙 정렬

- 커밋 상세 Actions 제목 옆에 노란색 `완료/전체 jobs (정수%)` 표시. 별도 진행 상태 줄·진행바 생략

- Actions 제목 옆에 첫 워크플로 시작부터 현재까지의 전체 경과 시간 표시. 전체 종료 시 마지막 상태 갱신 시각 기준으로 고정하며 병렬 실행 시간을 중복 합산하지 않음

- 개별 워크플로와 전체 진행률 모두 완료된 Job 수 / 전체 Job 수를 사용. Job이 전부 끝났어도 워크플로의 최종 상태가 확정되기 전에는 진행 중 아이콘 유지

- 최신순 상단 관찰 중에는 main 이후 다른 브랜치에서 늦게 도착한 최신 커밋도 따라감. 과거 탐색 중 위치 유지, 오래된 페이지·메타데이터만 변경 시 스크롤 이동 없음

- 새 최신 커밋은 짧은 부드러운 스크롤로 표시. 연속 응답에서도 최신 추적을 이어가며 사용자 스크롤 시 중단, 숨긴 탭·동작 줄이기는 즉시 이동

- 부분 이력은 내부 상태로만 관리하고 사용자 화면에 Partial history 문구나 해당 안내 툴팁을 표시하지 않음

- 커밋 상세를 닫으면 선택 상태도 함께 해제해 노드·Actions 링을 원래 크기로 복원. 닫기 버튼·바깥 클릭·Escape와 토큰 팝업 전환에 동일하게 적용하며 조회한 메타데이터 캐시는 유지

## 13. 개발자 디버그 모드

구현 구간·측정 의미·검증 기준은 [개발자 디버그 모드 명세](developer-debug-mode.md)를 따른다.

- 개발 환경 `Ctrl + Shift + D`, 배포 환경 `?debug=1`로 활성화하며 `?repo=`와 함께 사용할 수 있다. 주소창이 없는 PWA에서도 저장소 입력창에 `:debug`를 입력하고 제출해 패널을 열 수 있다. 명령은 API 조회·페이지 이동 없이 현재 저장소를 유지하며 일반 사용자에게 진입 버튼을 기본 노출하지 않는다.
- 기존 HTTP 카운터·캐시·요청 풀을 재사용하고 API 요청, 초기/수동/자동 갱신, DAG 레이아웃, Canvas 그리기를 구분한다.
- 종류별 최근 20개 측정을 메모리에 보관하고 민감 정보를 제외한 진단 JSON 복사와 Console 요약을 제공한다.
- 비활성 상태에서는 상세 계측·데이터 비교·측정 타이머·알림 렌더를 생략하며 인증·API·배포 동작을 바꾸지 않는다. 외부 전송·분석 서버·영속 저장소를 추가하지 않는다.

## 14. PWA

세부 요구사항·캐시 경계·업데이트 절차와 검증 한계는 [PWA 개발 명세](pwa.md)를 따른다.

- 고정 ID `/`와 `standalone` Manifest 및 기존 로고 파생 아이콘으로 모바일·데스크톱 설치를 지원한다. 설치 유도 UI는 추가하지 않는다.
- 정적 앱 셸만 Workbox precache에 저장한다. GitHub API·비공개 응답·PAT는 캐싱하지 않으며 기존 localStorage 인증 정책을 유지한다.
- 앱 버전 갱신은 GitHub 데이터 갱신과 분리하며 사용자 확인 후 적용한다. Later·실패 복구·오래된 자산 정리를 지원하고 다른 탭을 강제로 새로고침하지 않는다.
- 기존 Vercel Git Integration·브랜치 정책·Production Release 자동화는 유지하며 추가 Secrets·배포 CLI는 사용하지 않는다.
