# Commit Trail — 제품 명세

> Explore the flow of Git history.

이 문서는 현재 제품의 기능과 공통 제약을 요약한다. 기능별 상세 규칙과 구현 근거는 [문서 안내](README.md)에서 찾는다.

## 1. 개요

Commit Trail은 GitHub 저장소의 실제 커밋 부모·자식 관계를 **세로형 그래프**로 표시하는 오픈소스 웹앱이다.
`han41858/commit-trail`의 반응형 읽기 전용 SPA로, 자체 백엔드·데이터베이스 없이 정적으로 배포한다.
저장소 조회, 커밋 메타데이터, 자동 갱신, Split view와 PWA 설치를 지원한다.

## 2. 현재 기능

Split view는 저장소 1~32개를 가로 한 줄에 표시한다. 열마다 그래프·스크롤·고정 강조를 유지하며 상세 팝업과 갱신 일정은 공유한다.
최근 이력·직접 주소·Owner 조회로 대상을 추가하고, 왼쪽 `>` 탭의 **Manage repositories**와 **Apply changes**로 구성을 편집한다. 남아 있는 저장소의 탐색 상태와 공통 갱신 기한을 보존한다.

**Copy link**는 반복 `repo`·`branch`를 포함한 URL을 공유한다. 비공개 저장소·브랜치 이름도 URL에 노출되지만 접근 권한은 전달하지 않으며, 수신자가 적용한 PAT를 사용한다.
저장·정렬·복귀·URL 이력과 Escape 우선순위는 [Split view 명세](monitor-mode.md)를 따른다.

### 2.1 저장소 입력

- `https://github.com/owner/repo`와 `owner/repo`를 받는다. 입력·붙여넣기·URL의 `repo` 초기값을 소문자로 정규화하고 커서·선택 범위를 보존한다. 모바일 자동 대문자화·자동 수정·맞춤법 검사를 끈다. 지우기 버튼은 포커스와 그래프를 유지하고 입력값만 비운다.
- `owner`만 제출하면 공개 목록과 적용한 PAT로 볼 수 있는 목록을 합친다. 입력·필터링 중에는 조회하지 않으며 저장소를 선택하기 전까지 그래프를 유지한다. 페이지와 **Load more**, 일반 화면의 즉시 선택과 Split view의 **Add N repositories**는 [Owner 저장소 선택 명세](owner-repositories.md)를 따른다.
- 저장소 메타데이터, 기본 브랜치와 참조를 읽는다. 저장소와 명시한 기준 브랜치를 URL에 반영해 공유하고 새로고침 후 복원한다. URL에 저장소가 없으면 자동 조회하지 않는다.
- 빈 화면에는 `Follow your commit trail.`과 로고를 표시한다. `han41858/commit-trail` 데모는 중립 색상·점선 밑줄로 표시하고 외부 링크 화살표 없이 현재 화면에서 조회한다. 단일 뷰의 최초 조회나 저장소 전환 중 커밋이 없으면 중앙 제목을 `Loading...`으로 표시해 로딩을 알린다. 설명·데모 버튼은 화면과 접근성 트리·키보드 조작에서 제외하되 공간을 남겨 로고의 위치를 유지한다. 하단 로딩 인디케이터도 표시한다.
- 성공적으로 연 저장소 최근 10개는 [최근 방문 저장소 명세](recent-repositories.md)에 따라 로컬 자동완성에 사용한다. PAT 변경·삭제 시 비공개 이력을 정리하며, 브라우저 저장소 오류 시에도 주소 입력과 그래프는 사용할 수 있다.

### 2.2 공개·비공개 저장소

- 공개 저장소는 인증 없이 조회할 수 있다. 비공개 저장소는 사용자가 대상 저장소에 대해 발급한 **fine-grained PAT**로 조회한다. 토큰 패널은 비인증 IP당 시간당 약 60회, 인증 시 시간당 약 5,000회의 API 한도를 안내한다.
- 이력에는 `Contents: Read-only`, PR 기반 추천 집계에는 `Pull requests: Read-only`, Actions 모니터링에는 선택적으로 `Actions: Read-only`를 사용한다. Actions 권한이 부족해도 그래프는 유지한다.
- 토큰 패널은 적용한 토큰의 인증과 현재 저장소의 기능별 접근을 확인한다. `Permission`, `Used for`, `Check` 순서로 표시하고 권한은 Actions·Contents·Pull requests 순으로 정렬하며 `Read-only`를 보조 표시한다. ✅와 🚫는 각각 접근 가능과 접근 차단·만료를 뜻하며, 요청 제한·미확인은 별도 상태로 표시한다. `Recheck`와 `Create token`을 제공하며 로그인 ID·반복되는 저장소 설명·중첩 안내는 표시하지 않는다.
- API 제한 안내에서 토큰 패널을 열면 안내는 닫지만 재시도 제한은 유지한다. GitHub 발급 링크를 열면 토큰 패널을 닫는다.
- 적용한 토큰은 `localStorage`에 보관해 복원한다. 토큰 삭제 시 화면의 이력을 비우며, 브라우저 저장소가 쓰기를 막으면 저장 토큰을 지우지 못했음을 안내한다. 토큰은 GitHub API 요청에만 사용하며 URL, `sessionStorage`, IndexedDB, 로그, 분석 서비스에 노출하지 않는다. CSP·Service Worker 경계는 [PWA 인증 및 보안](pwa.md#6-인증-및-보안)을 따른다.

공개 저장소는 보통 IP당 시간당 60회, 인증 요청은 보통 시간당 5,000회 한도를 적용한다.
실제 한도는 인증 범위와 보조 제한에 따라 달라질 수 있다.
한도 오류는 권한 오류와 구분하고, 재시도 가능 시각까지 요청을 기다린다.
비인증 갱신의 토큰 필요 안내와 예외는 [갱신 명세](auto-refresh-and-metadata.md#94-비인증-자동-갱신)를 따른다.
PR 순위나 부가 메타데이터의 권한 오류는 기존 그래프를 지우지 않는다.

권한 확인은 토큰의 유효성을 먼저 확인하고 현재 저장소의 기능별 접근을 따로 검사한다.
토큰을 편집하면 **Apply token**으로 적용한 뒤 검사하며, **Recheck**로 다시 검사한다.
결과는 현재 저장소의 기능 접근을 뜻하며 PAT에 부여된 전체 권한 목록이 아니다. 결과는 저장하지 않는다.
토큰 패널은 발급 링크를 열기 전에 저장소 선택과 읽기 권한을 안내한다.
토큰 저장·삭제 오류는 패널에 표시하며 토큰을 분석 서비스에 보내지 않는다.
패널 문단의 줄 높이는 1.5, 제목 아래 여백은 12px를 사용한다.
`PopupBackdrop`은 배경 클릭이 완료된 뒤 닫아 가려진 컨트롤에 입력이 전달되지 않도록 한다.

### 2.3 세로형 커밋 그래프

- SHA당 원형 노드 하나를 두고 실제 부모 SHA로 분기·병합을 연결한다. 날짜가 역전되어도 위상 순서를 보존한다. 위상상 배치 가능한 커밋 중 커미터 시각(없거나 유효하지 않으면 작성 시각)이 최신인 커밋을 우선한다.
- **최신 → 과거(기본)**와 **과거 → 최신**을 전환한다. 전환하면 선택한 브랜치의 최신 또는 가장 오래된 이력부터 아래로 스크롤하며 읽는다.
- 브랜치 참조·경로·배치 레인을 구분한다. 색과 하이라이트는 공통 경로 ID를 사용하며 같은 색이라고 서로 다른 경로를 합치지 않는다. 현재 데이터가 같으면 같은 색을 사용하지만, 더 읽은 이력에 따라 경계와 색이 달라질 수 있다. 실제 브랜치 생성·통합 의도는 확정하지 않는다. [경로 색상과 하이라이트 명세](dag-hover-highlight.md)에 소유권과 색상 배정 규칙을 둔다.

### 2.4 커밋 인터랙션

- 노드·메시지·태그/릴리즈 아이콘을 클릭하거나 탭하면 해당 커밋을 선택해 상세를 연다. 상세에는 축약 SHA, 메시지, 작성자, 날짜와 GitHub 원본 링크를 표시한다.
- Hover는 툴팁이나 임시 경로 강조를 표시하며 커밋을 선택하거나 상세를 조회하지 않는다. 배지·연결선 클릭·탭은 상세를 닫고 경로를 고정한다. 강조 범위·유지·해제와 터치 판정은 [경로 하이라이트 명세](dag-hover-highlight.md#입력과-수명)를 따른다. 필수 동작은 Hover에 의존하지 않는다.
- 미조회 이력과 불완전한 관계를 완전한 데이터처럼 표시하지 않는다.

### 2.5 브랜치

초기 기준 브랜치는 일반 화면과 Split view에서 모두 URL의 `branch` → 저장소별 마지막 직접 선택 → `main` → `master` → GitHub 기본 브랜치 → 대체 후보 순으로 결정한다.
직접 선택만 저장 기록과 URL을 갱신하며, 자동 선택·URL 복원·자동 갱신은 기록을 덮어쓰지 않는다.
부분 목록에 없는 후보는 정확한 이름으로 확인하고, 삭제가 확인된 기록만 제거한다. 네트워크·권한·Rate Limit 오류에는 기록과 기존 그래프를 유지한다.
반복 `branch`는 반복 `repo` 순서와 대응하며 누락된 중간 값은 빈 값으로 보존한다. 대소문자·표준 URL 인코딩을 유지하고 탐색 이력과 새로고침에서 복원한다.

추천은 존재하는 `main`, `master`, 저장소 기본 브랜치를 앞에 한 번씩 표시하고, 나머지는 최근 90일간 병합 PR의 대상 횟수 순으로 추가해 최대 30개를 표시한다.
목록을 열면 PR을 소규모로 집계하며 부분 결과는 이어서 집계할 수 있다. 목록 밖 브랜치는 검색하거나 정확한 이름을 조회해 선택한다.

기준 HEAD의 첫 부모 경로는 직선 레인에 고정한다. 다른 브랜치와 병합 이력은 별도 레인에 배치하고 실제 부모 관계로만 연결한다.
공통 조상을 읽지 못했거나 관련이 없으면 기준선에 임의로 연결하지 않는다. 삭제된 참조의 이름도 추측하지 않는다.

- 추천 목록을 열 때만 PR 집계를 시작해 배치당 최대 3페이지를 처리한다. 부분 집계 개수에는 `+`를 붙이고 **Continue PR ranking**으로 이어서 집계한다. 저장된 선택은 추천 순서를 바꾸지 않는다.
- 현재 존재하는 브랜치만 추천한다. 검색은 로딩한 이름을 필터링하고 **Find exact branch**로 목록 밖의 브랜치를 직접 조회한다.
- 현재의 완전한 목록이 후보 부재를 확인하면 정확한 이름을 추가 조회하지 않는다. URL 브랜치 조회 실패 시 기존 그래프를 유지하며 재시도할 수 있다.
- `commit-trail.branch-selections`는 직접 선택한 저장소·브랜치·공개 여부만 저장한다. 저장소는 소문자로 정규화하고 브랜치의 대소문자는 보존한다. 기존 메타데이터로 공개 여부를 갱신하며 별도 API 요청은 하지 않는다.
- PAT 등록·교체·삭제 시 공개 선택은 유지하고 비공개 선택을 제거한다. 오래된 인증 탭은 다른 인증 문맥의 비공개 선택을 노출하거나 덮어쓰지 않는다. 브라우저 저장소에 접근하지 못해도 브랜치를 선택할 수 있다.
- 배지는 보이는 경로 근처에 표시한다. 화면을 지나는 병합 곡선도 포함하며, 고유 경로의 이름은 합류 지점까지 표시한다. 처음부터 기준선에 있는 참조는 보이는 공통 이력에 함께 표시한다.
- 구분 가능한 가장 짧은 경로 접미사를 사용하고, 폭이 모자라면 뒤를 `…`로 줄인다. 같은 SHA의 참조는 기준 브랜치를 맨 위에, 나머지를 이름순으로 나열하며 `+N`으로 숨기지 않는다. 화면보다 큰 묶음은 HEAD에 고정하고 스크롤 영역을 확보한다. 커밋 좌표·레인·행 간격은 바꾸지 않는다.
- 기준 브랜치 묶음을 우선하고 그 외에는 긴 이름의 공간을 먼저 확보한다. HEAD 행과 가까운 경로, 기존 배지 가장자리 등에서 이름이 겹치지 않는 후보를 고른다. 짧은 경로에서는 한 행(31px) 안을 먼저 찾고 필요한 때만 가까운 빈 위치로 이동한다.
- 배지는 노드·Actions 링·선을 덮을 수 있으나 메시지·SHA·작성자의 표시·입력 영역에는 들어가지 않는다. 메시지를 숨긴 화면은 그래프 전체를 사용한다. 표시 폭은 경로 앵커가 아닌 그래프 영역을 기준으로 정한다. 선명한 글자와 약 40% 불투명도의 경로색 배경을 사용하며 노드·링의 입력 판정을 우선한다.
- 이름이 줄었을 때만 Hover 또는 탭으로 전체 이름을 즉시 표시한다. 긴 이름은 화면 안에서 줄바꿈한다. Hover 툴팁은 포인터가 벗어나면 닫고 탭으로 고정한 툴팁은 유지한다. 다른 곳 누르기, 어느 열에서든 스크롤, Escape 또는 화면 변경 시 닫는다. 전체 이름은 브랜치 선택 메뉴에서도 확인할 수 있다.
- 배경의 기본 표면 불투명도는 35%이며, 그 위에 경로 색상을 라이트 6%·다크 8%로 겹쳐 전체 약 40%를 유지한다.

### 2.6 반응형

화면 배치는 기기 종류가 아닌 너비로 구분한다. 일반 화면은 브라우저 뷰포트, Split view는 각 열의 실제 너비가 800px 이하이면 좁은 화면, 초과이면 넓은 화면 배치를 사용한다. Hover 가능 여부와 터치 입력은 너비와 별도로 판정한다.

일반 화면과 Split view는 세로로 스크롤한다. 좁은 화면에서는 레인을 압축해 모든 브랜치를 표시한다.
메시지 공간을 확보하고도 실제 레인 간격이 12px 이상이면 브랜치 영역을 최대 50%로 제한하고 옆에 최대 50% 너비로 12px 크기의 한 줄 메시지를 표시한다.
간격이 부족하면 메시지와 그 입력 영역을 숨기고 전체 너비를 그래프에 사용한다. 메시지를 숨겨도 노드를 탭해 상세를 연다. 이 자동 전환은 GitHub API를 호출하지 않는다.

넓은 화면은 실제 레인에 필요한 너비만 사용하며 브랜치 영역과 메시지·SHA·작성자 너비를 각각 최대 50%로 제한한다.
31px 커밋 간격 안에서 같은 커밋의 메시지와 SHA·작성자 줄을 가깝게 묶고 긴 글은 줄여 표시한다. 상세에서 전체 내용을 확인한다.

## 3. UI 원칙

- 그래프를 전체 뷰포트에 그리고 배경·테두리·그림자 없는 헤더에 저장소·기준 브랜치·방향 컨트롤을 둔다. 넓은 화면의 주소 입력 기본 폭은 220px이며 실행은 접근성 이름이 있는 돋보기 버튼으로 제공한다. 기준 브랜치를 고르기 전에는 `Branch`, 고른 뒤에는 실제 이름을 표시한다. 방향은 `↓ Older` / `↓ Newer`, 툴팁과 접근성 이름으로 안내한다.
- 토큰·설정·Split view 선택 창은 검정 45% 반투명 배경을 공유한다. 설정은 `•••` 아래 오른쪽, 토큰·Split view는 중앙에 배치하고 작은 화면에서는 Safe Area 안에서 내부 스크롤을 제공한다. 바깥 배경에서 누르고 놓은 클릭·탭만 창을 닫는다. 경계를 가로지르는 드래그·취소된 터치와 내부 조작은 창을 닫지 않는다. 토큰·설정·브랜치·커밋 상세는 Escape로도 닫으며, 브랜치·최근 저장소·검색 추천 목록은 별도 어두운 배경 없이 해당 입력이나 버튼 근처에 표시한다.
- 상세는 해시와 오른쪽 정렬 authored 시각을 한 줄에 표시한다. 제목 뒤에 작은 회색 `by 이름`을 붙이고 본문을 표시하며, GitHub 아이콘 링크는 닫기 버튼 옆에 둔다. 필드명·부모 정보·커밋 선택 셀렉트는 표시하지 않는다. 하단 안내가 있으면 8px 여백을 확보하고 내부 스크롤·포커스를 유지한다. 자세한 배치는 [상세 팝업 배치](monitor-mode.md#커밋-상세와-하단-고정-안내의-배치)를 따른다.
- 커밋 제목은 줄 높이 1.4, 본문은 1.45와 위쪽 여백 8px을 사용한다. 본문 앞뒤의 빈 구분 줄은 생략하되 들여쓰기·내부 빈 줄·내용 줄의 공백은 보존한다. 본문과 메타데이터가 있는 내용 영역만 스크롤하고, 닫기·GitHub 링크·Split view의 저장소 이름은 고정한다. 다른 커밋을 선택하면 내용 영역을 맨 위로 되돌린다.
- 하단에 커밋 수와 로딩 상태를 표시한다. 좁은 화면은 내용에 필요한 너비만 사용하며 커밋 수 앞에 장식용 점을 표시하지 않는다. 실제 진행 중인 GitHub 요청만 `x5`처럼 계수한다. 일반 화면은 전체를, Split view는 해당 열의 저장소를 센다. 1~4개는 느리게, 5~8개는 보통, 9개 이상은 빠르게 회전한다. 0개이면 숫자를 숨기고 후처리 중에는 인디케이터만 남길 수 있다. 동작 줄이기 설정에서는 회전을 멈추고 개수는 유지한다.
- 최초 로딩의 `Loading...` 제목은 공손한 live region으로 알린다. 설명과 데모 버튼은 숨기고 버튼 조작을 막되 기존 공간을 유지한다.
- 요청 수는 실제 HTTP 전송부터 응답 본문 파싱이 끝날 때까지 집계하고 완료·실패·취소 시 정리한다. 이력과 메타데이터를 모두 포함하며 진행 중에만 메모리에 보관한다. 집계만을 위한 API 요청·타이머·저장 키·진단 출력은 추가하지 않는다.
- 설정은 시스템 테마를 기본으로 밝은·어두운 테마와 공통 갱신 옵션을 제공한다. 설정 하단의 `Built at`은 Vite가 포함한 UTC 빌드 시각을 브라우저 현지 날짜와 24시간제 `HH:mm`으로 한 줄에 표시한다. 초·오전/오후·시간대 이름은 생략한다. `<time dateTime>`에 원본 UTC 값을 두고, 화면과 Safe Area 안에서 잘린 표기는 `title`에 전체 시각을 남긴다. 타이머·저장소·API를 사용하지 않으며 개발 서버는 `Development`로 표시한다.
- [날짜 구분선 명세](date-separators.md)에 따라 브라우저 현지 시간대의 확인된 월·일 경계를 표시한다. 로딩한 전체 이력에서 대표 커밋을 정하며, 부분 로딩의 가장 오래된 월·일이나 커밋이 없는 날짜에 임의로 구분선을 긋지 않는다. 날짜 역전에도 DAG 순서와 스크롤을 유지한다.
- 과거 이력 스크롤 안내, 배경 파티클과 3D 효과는 표시하지 않는다. 우주·궤도 모티브는 점과 선의 표현에 사용한다.

| 영역          | 현재 구현                            |
| ------------- | ------------------------------------ |
| 프레임워크    | React + TypeScript                   |
| 빌드          | Vite                                 |
| 그래프        | Canvas 2D                            |
| 레이아웃      | Git DAG 전용 레인 배치 알고리즘      |
| 보조 유틸리티 | 전용 TypeScript 모듈, D3 의존성 없음 |
| 데이터        | GitHub REST API                      |
| 배포          | 정적 호스팅                          |

데이터 모델, DAG 레이아웃, 렌더러를 분리한다. Force Simulation, Three.js, PixiJS, WebGL은 사용하지 않는다.
별도 의존성은 필요한 경우에만 추가하고, 레이아웃 계산의 UI 지연이 측정되면 Web Worker를 검토한다.

## 5. 데이터 처리 및 정확성

### 5.1 모델

Commit은 SHA로 식별하고 부모 SHA 목록, 메시지, 작성자, 작성·커밋 일시와 GitHub URL을 보유한다.
Branch는 이름과 HEAD SHA를 가진 참조(`name`, `commit.sha`)이며, 저장소 기본 브랜치 이름은 `HistorySnapshot.meta.default_branch`로 따로 관리한다.

### 5.2 API 및 로딩

선택한 기준 브랜치에서 시작해 GitHub REST API 페이지당 최대 100개 커밋을 읽는다. 최신순은 미조회 부모 SHA에서 시작해 참조가 삭제된 분기를 포함한 모든 실제 병합 부모를 따라간다.
오래된 순은 첫 응답의 마지막 페이지 링크로 가장 오래된 페이지를 찾고, 고정한 HEAD SHA에서 페이지 번호를 줄이며 최신 방향으로 읽는다.
전체 이력을 선행 다운로드하거나 이름순 브랜치 목록을 커밋 조회에 사용하지 않는다. 참조 목록은 선택과 이름 표시용이다.

**독립 브랜치 탐색.** 최근 1년의 push·PR 머지·머지 큐 활동을 시간 역순으로 읽고, 기준 이력의 현재 날짜 구간에 맞는 독립 브랜치를 확장한다. 저장소 전체 이력을 대표하지는 않는다.
`Link`의 `after` 커서를 따라 배치당 활동 1페이지와 독립 이력 최대 3개를 처리한다. 중복 HEAD·공유 조상과 구간 밖 오래된 이력은 제외한다.
오래된 순은 기준 이력이 현재에 이른 뒤 독립 이력을 추가한다. 활동에 없는 휴면 브랜치는 직접 선택한다.
반복·누락 커서나 활동 오류는 자동 재시도를 막고 기준 이력을 유지한다. 활동 오류는 별도로 재시도할 수 있고, 구간에서 결과가 없던 브랜치는 탐색 구간이 과거로 넓어지면 다시 확인한다.

**자동으로 읽는 경계.** 두 방향 모두 가로 표시 범위 안에서 현재 화면 하단 이전의 미완료 경계를 읽는다. 화면 위쪽 경계도 포함하고, End·Home·큰 점프 후에도 과거의 최대 스크롤 범위를 사용하지 않는다.
루트·이미 로딩한 합류점·화면 아래나 가로 범위 밖의 경계에서는 새 조회를 시작하지 않는다. 이미 등록한 작업은 화면에서 벗어났다는 이유로 취소하지 않는다.
이력이 삽입되면 새 좌표로 판정하고, 최신 추적 애니메이션 중에는 조회를 멈췄다가 도착한 화면에서 다시 판정한다. 필요한 페이지 수를 임의로 제한하지 않는다.
미조회 부모와 분기 경계는 그래프에서 구분한다.

**요청 수명.** 각 `History`의 커밋 요청 풀은 최대 16개를 병렬 실행한다. Split view의 저장소별 풀과 메타데이터 요청은 독립이므로 앱 전체 HTTP 상한은 아니다.
경계를 실행 전에 대기열에 등록하고 중복 경계·요청을 공유한다. 완료 결과는 즉시 반영하고 대기열에서 제거한 뒤, 미완료 활동 경계가 여전히 보이면 다시 판정한다.
저장소·방향·토큰 변경 시 대기·실행 요청을 취소한다. 일부 실패에도 성공한 결과는 유지하며 자동 요청을 멈춘 뒤 실패 경계만 재시도한다.

**페이지 캐시와 삭제 경계.** 날짜 필터 없는 고정 SHA의 첫 페이지는 요청 커밋을 포함해야 수용하고 캐시한다. 빈 응답 또는 요청 SHA가 빠진 응답은 경계를 완료하지 않고 재시도 오류를 표시한다. 날짜 필터 조회와 오래된 순의 후속 페이지에는 HEAD 포함을 강제하지 않는다.
부모 커밋의 현재 존재 여부로 경계를 판정한다. 브랜치 정리 후 다시 필요한 부모는 경계로 복원하고 유효한 고정 SHA 페이지를 재사용한다.
사라진 경계의 늦은 응답은 그래프에 다시 합치지 않는다. 해당 경계만의 오류는 무시하되 인증 실패와 Rate Limit은 계속 안내한다.

부분 데이터가 합쳐져도 불필요한 레인 이동을 줄이고, 앞에 새 행이 삽입되면 보던 커밋 위치를 보존한다.
경로·인접 관계·색상 재계산은 [경로 색상 명세](dag-hover-highlight.md#결정적-색상-배정)를 따른다.

### 5.3 렌더링과 성능

Canvas 2D는 `devicePixelRatio`를 반영해 현재 뷰포트와 소량의 여유 영역만 그린다. 가상 스크롤과 점진적 로딩으로 대량 DOM 생성을 피한다.
스크롤·선택·크기 변경 시 필요한 프레임을 그리며, `contextrestored`가 발생하면 비어 있는 Canvas를 즉시 다시 그린다.
DAG 레이아웃은 부모 관계를 유지하면서 선 교차, 불필요한 좌우 폭과 부분 데이터에 따른 레인 급변을 줄인다.

GitHub 이력은 메모리에서 재사용하며 영속 캐시에 저장하지 않는다. 성능 변경 시 `angular/angular` 같은 대형 공개 저장소로 확인하고, 필요하면 커밋 1천/1만/10만 개 수준의 합성 데이터로 나누어 조회·렌더링 한계를 실측한다. 이 수치는 지원 한도를 뜻하지 않는다.

## 6. 오류와 빈 상태

잘못된 입력, 없거나 접근할 수 없는 저장소, 잘못된 PAT, 네트워크 장애와 일부 요청 실패를 안내한다.
Rate Limit은 권한 오류와 구분하고 초기화 시각을 표시하며 이른 재시도를 막는다.
빈 저장소와 일부 브랜치·부모 미조회 상태를 구분하며, 토큰과 민감한 응답을 오류에 노출하지 않는다.

## 7. 검증

그래프 변경 시 선형 이력·분기·두 브랜치 병합·다중 부모·공유 커밋이 실제 부모 SHA와 일치하는지 확인한다.
방향 전환, 후속 페이지, 미조회 경계, 참조가 삭제된 이력과 API 오류도 자동 테스트로 검증한다.
브라우저에서는 공개·비공개 조회, 링크 복원과 커밋 상세, 토큰 삭제, 좁은 화면 입력, 점진적 로딩과 오류 표시를 확인한다.
배포·실제 API의 검증 한계는 [기술 가이드](technical-guide.md#before-publishing), PWA 설치의 검증 한계는 [PWA 명세](pwa.md#8-검증)를 따른다.

## 8. 현재 범위에서 제외

Push·Merge·Rebase 등 쓰기 작업, PR 생성·수정·병합, Actions 관리, GitHub 로그인·OAuth·GitHub App은 제공하지 않는다.
서버 측 Git Clone, 별도 백엔드·DB, Diff·파일 비교, 배포 반영 상태 분석, AI 분석, 3D/WebGL, 그래프 이미지 내보내기, 협업이나 복잡한 통계 대시보드도 범위에서 제외한다.

## 9. 자동 갱신 및 커밋 메타데이터

GitHub 변경은 설정한 주기로 자동 확인하거나 수동으로 갱신한다. 과거를 탐색하는 위치는 유지하고 최신 이력을 보고 있으면 새 커밋을 따라간다.
완료 시각은 성공 여부와 구분하고 부분 조회·실패를 삭제나 정보 부재로 확정하지 않는다.
태그·릴리즈·Actions는 커밋에 연결하되 DAG 배치를 바꾸지 않는다. GitHub Release는 실제 배포 상태를 뜻하지 않는다.
주기, 브랜치 후속 확인, 증분 반영, 캐시와 상태 집계는 [자동 갱신 및 메타데이터 명세](auto-refresh-and-metadata.md)를 따른다.

## 10. 개발자 디버그 모드

기본 화면에 진단 진입 버튼을 표시하지 않는다. 활성화 시 API·갱신·DAG·Canvas 측정과 민감 데이터를 제외한 진단 복사를 제공한다.
진단은 인증·조회 정책을 바꾸지 않고 측정값을 영속 저장하거나 외부로 전송하지 않는다. 활성화 방법과 계측 범위는 [개발자 디버그 모드 명세](developer-debug-mode.md)를 따른다.

## 11. PWA

지원하는 모바일·데스크톱 브라우저에서 설치할 수 있으며, 설치 앱도 같은 그래프와 인증 정책을 사용한다.
Service Worker는 정적 앱 셸만 캐시한다. 앱 버전 업데이트는 GitHub 데이터 갱신과 별개로 승인한 창에 적용한다.
Manifest·Safe Area·캐시 경계·배포·복구·실기기 검증은 [PWA 명세](pwa.md)를 따른다.
