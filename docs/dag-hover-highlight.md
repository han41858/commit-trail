# Commit Trail — Git DAG 브랜치 흐름 하이라이트

## 목적과 공통 정책

브랜치가 어디에서 시작해 어떤 커밋을 거쳐 어디로 병합됐는지, 화면에 표시된 흐름의 시작과 끝을 함께 따라가도록 한다. 명시적 병합선은 **이번 병합/승격으로 새로 유입된 구간과 해당 병합점**을 표시한다. 이전에 목적지에 반영된 전체 이력은 포함하지 않으며 시작 위치를 보여주는 경계 커밋까지만 포함한다. 노드·브랜치 배지의 기존 기본 흐름 강조는 유지한다.

- 브랜치 이름과 커밋 노드·보이는 메시지의 Hover·클릭·탭은 같은 기본 흐름 판정을 사용한다. 연결선도 실제 부모 관계를 재사용하되 명시적으로 가리킨 병합선은 그 병합으로 새로 유입된 구간을 표시한다.
- 해당 흐름의 첫 번째 부모(`parents[0]`) 연결·시작 경계와 HEAD를 받아들이는 종료 병합·연결선을 강조한다. 두 경계 너머의 조상 전체·다른 병합 부모·후속 이력으로 확장하지 않는다.
- 넓은/좁은 일반 화면과 모든 Split view 열에 같은 정책을 적용한다. 너비와 포인터 종류는 배치·Hover 가능 여부에만 사용한다.
- 기존 Canvas 2D, 레인·색상·31px 행 간격·배지 배치·클릭 영역과 상세 팝업을 유지한다.

## 강조 범위

### 브랜치 이름

실제 참조 HEAD에서 그 브랜치의 흐름을 따라간다. 시작 쪽에서는 다른 흐름과 만나는 노드와 그 노드까지의 연결선을 포함하고 그 이전 공통 이력은 흐리게 표시한다. 종료 쪽에서는 HEAD를 받아들이는 병합 커밋과 정확한 연결선을 포함하고 그 커밋의 다른 이력은 따라가지 않는다.

같은 HEAD를 가리키는 이름 배지들은 각각 유지한다. 명시적으로 Hover한 이름만 선명하게 표시하고 다른 이름을 임의로 선택하지 않는다.

### 커밋 노드·메시지·선택

중간 커밋을 대상으로 하더라도 해당 흐름 전체와 양쪽 경계를 표시한다. 같은 흐름의 HEAD 쪽 커밋·시작 경계·종료 병합을 함께 보여주므로 노드 사이를 이동해도 강조 범위가 바뀌지 않는다.

- 알려진 다른 HEAD를 만나거나 이미 다른 흐름이 차지한 첫 번째 부모에 도달하면 경계로 포함하고 종료한다.
- 시작 또는 종료 경계 노드 자체를 선택하면 그 노드가 실제로 속한 흐름을 표시한다. 자식 브랜치가 경계를 포함했다는 이유로 그 자식 흐름들을 모두 강조하지 않는다.
- 브랜치 이름이 삭제된 과거 커밋도 로딩된 DAG의 첫 번째 부모 관계로 흐름을 찾는다. 이름을 복원하거나 새 이름을 추측하지 않는다.
- 시작점은 현재 조회된 DAG에서 확인한 분기·공유 HEAD 경계이다. 미조회 구간을 실제 루트나 정확한 브랜치 생성 시점으로 단정하지 않는다.
- 숨겨진 메시지에는 별도 Hover·클릭 영역을 만들지 않는다.

### 연결선 Hover

- 포인터가 실제 Canvas 곡선에서 5 CSS px 이내에 있으면 해당 선을 Hover 대상으로 삼는다. 직선과 곡선, 방향 반전·스크롤·DPR 변경·좁은 열에서도 같은 그래프 좌표를 사용한다.
- 첫 번째 부모 연결선은 기본적으로 자식 커밋의 흐름을 사용한다. 두 번째 이후 부모의 병합선은 해당 부모부터 첫 번째 부모를 따라 그 병합 당시의 구간과 명시된 병합점을 표시한다. 현재 브랜치 HEAD나 병합 뒤의 작업으로 확장하지 않는다. 유입 경로에서 목적지의 첫 부모 이력에 이미 포함된 가장 가까운 공통 커밋을 시작 경계로 포함하고 멈춘다. 현재 중간 커밋을 가리키는 다른 참조나 소유 흐름 변화는 이 구간을 끊지 않는다. 공통 경계를 찾을 때 목적지의 실제 병합 부모도 확인하지만 그 이력을 강조하지는 않는다. 미조회 등으로 공통 경계를 확인할 수 없을 때만 첫 소유 흐름 경계를 대체 범위로 사용하며, 탐색이 그 경계를 넘어갔다면 경계까지 다시 제한한다. 다른 흐름의 경계 너머로 미조회 점선을 추가하지 않는다.
- 예를 들어 `e1ac3b8 = merge(f2ec8d4, a4304a2)`, 이전 배포 `f2ec8d4`에 `98b49e1`이 포함돼 있으면 `e1ac3b8 → a4304a2 → 98b49e1`만 강조한다. 현재 dev HEAD와 이후 작업, 이전 main 배포·그 이전 dev 이력은 제외한다. 같은 부모가 여러 곳에 병합됐어도 해당 병합점만 표시한다. 브랜치 배지는 유입 부모 SHA가 실제 현재 참조 HEAD일 때만 선명하게 표시한다.
- 병합 구간을 가리킨 뒤 그 구간의 첫 부모 선으로 이동하면 같은 범위를 유지한다. 노드·배지 자체는 기존 판정을 우선하며, 기존 dev 커밋이 상세에서 선택돼 있어도 병합선 Hover는 당시 구간을 임시 우선한다. 이 구간 표시는 기본 브랜치의 종료 판정을 바꾸거나 브랜치 삭제·통합 완료를 확정하지 않는다. 특정 브랜치 이름을 하드코딩하지 않는다.
- 노드·배지·보이는 메시지 판정을 먼저 적용한다. 겹치는 선 중에서는 실제 곡선에 더 가까운 선을 고르고, 거리 차이가 0.5px 이하이면 현재 강조 흐름을 유지한다. 기존 강조가 없고 서로 다른 흐름의 선을 구분할 수 없는 교차점에서는 임의로 하나를 고르지 않는다.
- 미조회 첫 번째 부모의 점선은 알려진 자식 흐름에 연결한다. 병합 부모의 흐름이 미조회 상태면 임의의 브랜치로 연결하거나 추가 이력을 요청하지 않는다.
- 선 Hover는 커밋 선택·상세 조회를 시작하지 않는다. 별도 선 클릭·탭 동작을 추가하지 않고 기존 노드의 넉넉한 클릭·탭 영역과 터치 스크롤을 유지한다.

### 병합

통합 브랜치 내부에서는 병합 커밋과 첫 번째 부모를 잇는 주 흐름을 강조하고, 병합으로 들어온 다른 작업 브랜치와 그 연결선은 흐리게 표시한다. 현재 선택한 기준 HEAD(`baseHead`)의 흐름은 종료 판정에서 제외한다. 작업 브랜치가 기준 흐름을 받아온 동기화 병합을 기준 흐름의 종료로 오인하지 않기 위한 규칙이며 특정 브랜치 이름에 의존하지 않는다.

작업 브랜치에서는 그 작업 흐름과 시작 경계, 종료 병합 커밋과 `종료 병합 → 흐름 HEAD` 연결선을 강조한다. 종료 커밋의 다른 부모·후속 커밋·다른 병합 브랜치는 제외한다.

- 종료 병합은 기준 흐름 외의 작업 HEAD를 두 번째 이후 부모로 받아들이고 다른 흐름에 속하는 커밋이다. 첫 번째 부모는 대상 흐름의 연속을 뜻하므로 종료로 표시하지 않는다. 부모가 하나뿐인 단순 분기도 종료가 아니다.
- HEAD가 아닌 중간 커밋만 병합된 뒤 작업이 계속됐다면 그 과거 병합은 현재 흐름의 종료점으로 표시하지 않는다.
- 동일 HEAD를 여러 흐름에 병합했다면 조회된 종료점들을 각각 표시하되 그 너머로는 확장하지 않는다. 이는 관찰된 병합 경계이며 브랜치가 삭제됐다는 의미는 아니다.
- 아직 병합되지 않았거나 종료 커밋이 미조회 상태면 현재 HEAD까지 표시한다. 종료점을 찾기 위한 추가 요청은 하지 않으며 새 데이터가 도착하면 기존 인덱스를 다시 계산한다.

기준 흐름을 받아오는 동기화 병합은 기준 흐름의 종료에서 제외한다. 기준 `main: m2 → m1`, 작업 `F3 = merge(f2, m2)`, `f2 → f1 → m1`에서 `main`은 `m2,m1`만 강조하며 `F3`를 종료로 표시하지 않는다. 이후 기준에 `m3 = merge(m2, F3)`가 추가되면 작업 흐름은 `m3`와 `m3 → F3`를 종료 경계로 포함한다.

`topic=H`, `topic2=N(H)`와 `topic2=M(H,o1)`는 모두 `H`에서 첫 번째 부모로 이어지는 흐름이다. 두 경우 모두 `topic`의 종료를 추가하지 않는다. 후자의 `o1` 흐름은 두 번째 부모로 유입되므로 기준 흐름이 아니라면 `M`을 종료로 표시할 수 있다.

### 종료 판정의 한계

종료 표시는 조회된 부모·참조 HEAD와 현재 기준 흐름을 이용한 휴리스틱이다. 커밋만으로 모든 브랜치 간 동기화·통합 의도를 구분하지 않는다. 기준이 아닌 통합 브랜치를 작업이 받아오면 그 동기화도 종료로 표시될 수 있으며, 기준 흐름이 다른 브랜치로 승격돼도 기준 흐름의 종료는 표시하지 않는다.

`P = merge(m1, d2)`, `F3 = merge(f1, d2)`, `d2 → d1`이고 참조가 `main=P`, `dev=d2`, `feature=F3`인 예에서는 다음과 같다.

| 현재 기준 | `dev` 강조 | 판정 한계 |
| --- | --- | --- |
| `main` | `d2,d1`과 `P → d2`, `F3 → d2` | 실제 승격 `P`와 동기화 `F3`를 모두 종료로 포함 |
| `dev` | `d2,d1` | 기준 흐름 제외 규칙으로 실제 승격 `P`도 종료로 표시하지 않음 |

이는 흐름 표시의 한계이며 브랜치의 실제 생성·삭제·통합 완료를 확정하는 정보가 아니다. 특정 이름을 하드코딩하거나 이를 구분하기 위한 추가 API 요청은 하지 않는다.

### 예시

- `merge`의 부모가 `base, feature`이고 `feature → base → root`라면, 작업 흐름은 `merge(종료) → feature → base(시작)`이다. `base → root`, `merge → base`는 비대상이며 종료 병합의 다른 이력으로 확장하지 않는다.
- `d4 → d3 → d2 → d1`에서 `dev=d4`, `main=d2`이면 `dev` 흐름은 `d4,d3,d2`이며 `d1`은 제외한다. `main` 흐름은 `d2,d1`이다. `d3` Hover·선택도 `dev` 배지와 같은 흐름을 표시한다.
- 첨부 사례의 `24c26bf`는 `364ac3e`에서 시작해 `373287d`로 병합된 작업 흐름이다. `373287d → 24c26bf → 364ac3e`와 양쪽 경계 노드는 포함하지만 `99d783d`, `8c2c0ee`, `25069fd` 등 이전·병합 이력은 따라가지 않는다.

## 불투명도

| 요소 | 대상 | 비대상 |
| --- | --- | --- |
| 노드·메시지 | 기존 100% | 25% |
| 연결선·배지·SHA·작성자 | 기존 값 | 기존 값 × 0.25 |
| Actions 도넛·진행률 호·회전 링 | 기존 값 | 기존 값 × 0.25 |
| 태그·릴리즈 아이콘 | 기존 값 | 기존 값 |

Actions는 상태 색상·선 두께·반지름·Job 완료율과 회전 시작 시각을 유지한다. 진행 배경의 0.25, 대기·취소·건너뜀의 0.4에도 비대상 배율을 상대적으로 곱한다. Job 수 미확정 DOM 회전 링도 같은 정책을 사용한다.

기존 선택 노드 크기와 상세 정보, 말줄임된 이름의 전체 툴팁·위치·개별 배지·충돌 회피는 유지한다.

대상이 바뀌거나 강조가 해제되면 불투명도만 약 140ms 동안 부드럽게 전환한다. 도중에 다른 대상으로 이동하면 현재 표시 중인 값에서 새 목표로 이어지며, 전체 밝기로 초기화하지 않는다. 노드·메시지·연결선·배지와 Canvas/DOM Actions 링은 같은 시간과 보간 배율을 사용한다. 새 설정이나 토글은 추가하지 않는다.

## 입력과 수명

- `(any-hover: hover)`를 지원하는 포인터는 마우스 이동으로 임시 강조한다. Hover만으로 선택하거나 상세를 조회하지 않는다.
- 클릭·탭은 기존 상세와 함께 선택 흐름을 표시한다. Hover는 선택보다 임시 우선하며, Hover 해제 후에는 유효한 선택 흐름으로 돌아간다.
- 커밋 사이의 빈틈에서는 최대 100ms 이전 Hover를 유지해 전체 밝기로 깜빡이지 않게 한다. 새 대상은 즉시 전환 목표로 적용하고 이전 해제 예약을 취소한다. 같은 대상 재진입도 예약을 취소하며, 반복 빈 공간 이동으로 기한을 연장하지 않는다.
- 그래프 이탈·스크롤·blur·크기/열 순서 변경은 Hover 대상을 즉시 해제하고 불투명도는 유효한 선택 또는 기본값으로 전환한다. 클릭·터치·종료·언마운트도 해제 예약을 정리해 늦은 콜백이 새 흐름을 지우지 않게 한다.
- 상세 닫기·빈 공간 클릭/탭·다른 저장소 선택 등으로 기존 선택이 해제되면 선택 강조도 해제한다. 선택이 유지되는 크기·순서 변경에서는 유효한 흐름을 유지한다.
- 터치 시작·스와이프·롱 프레스·취소된 포인터만으로 새 선택을 만들지 않는다. 기존 터치 스크롤을 유지한다.
- 각 Graph가 독립 처리한다. 같은 SHA를 가진 다른 저장소나 다른 Split view 열을 흐리게 만들지 않는다.

## 구현과 성능

`graphHoverIndex()`가 렌더러의 위상 순서, 실제 첫 번째 부모와 참조 HEAD로 노드의 흐름 소유자를 계산한다. 기준 HEAD, 알려진 HEAD, 이름 없는 나머지 경로 순서로 각 노드를 한 번씩 배정하며 다른 알려진 HEAD를 넘어 차지하지 않는다. 병합 부모 관계도 한 번 인덱싱해 각 흐름 HEAD를 받아들이는 종료 병합만 기록한다.

기본 흐름 식별자는 HEAD SHA, 명시적 병합 구간은 병합 커밋·유입 부모 SHA 쌍이다. 색상 값·레인 번호·좌표를 식별자로 사용하지 않는다. 같은 색이 재사용되거나 같은 레인에 있어도 다른 경로를 합치지 않는다. `branchTracks()`는 이름과 HEAD의 연결에 재사용하며, 배지 배치 자체는 변경하지 않는다.

`resolveGraphHover()`가 배지·커밋 Hover와 선택에 같은 흐름 결과를 제공한다. 최근 두 흐름만 캐시하고, 한 흐름의 여러 커밋과 선택은 같은 결과를 재사용한다. 전환이 끝난 뒤 같은 흐름 안의 이동은 추가 Canvas 다시 그리기를 만들지 않는다.

명시적 병합 구간도 같은 두 항목 캐시를 공유한다. 첫 부모 경로는 필요할 때만 늘리고, 인덱스 생성 시 저장한 위상 순서로 이미 찾은 공통 경계보다 오래된 목적지 조상을 제외한다. 반복 조회는 캐시를 재사용하며 추가 API·데이터 구조 변경 없이 현재 로딩된 부모 관계만 사용한다. 목적지 이력 탐색은 경계를 찾기 위한 계산이며 다른 부모를 강조 범위에 넣지 않는다.

`GraphOpacity`는 비대상 요소의 공통 불투명도 하나와 개별 예외의 시작값·목표값으로 140ms smoothstep 보간을 계산한다. 대상 변경 시 이전/다음 강조 집합과 아직 전환 중인 예외만 순회한다. A→B→C로 빠르게 옮겨도 직전 B와 다음 C에 없는 A의 표시값을 보존한다. 기존 노드·간선·참조 Map의 `has`·`size`만 재사용하며 전체 요소 집합을 복제하거나 순회하지 않는다. 비용은 강조 범위와 진행 중인 예외 크기에 비례한다. 새로 로딩된 비대상 요소는 현재 공통 불투명도로 표시해 함께 전환하고, 삭제된 예외와 완료된 예외는 정리한다.

전환 중에만 `requestAnimationFrame`으로 다시 그리며 완료 후에는 중단한다. 공통 값이나 개별 예외가 실제 표시 요소의 밝기를 바꾸지 않으면 프레임을 예약하지 않는다. 프레임마다 React 상태나 DAG 레이아웃을 갱신하지 않는다. DOM 회전 링은 Canvas 노드와 같은 프레임의 불투명도를 적용하고 회전 애니메이션은 다시 시작하지 않는다. 같은 결과나 동등한 데이터로 다시 렌더링해도 전환 종료 시점을 연장하지 않는다. 비활성화·언마운트·그리기 효과 교체 시 이전 프레임을 취소한다. 뷰포트/데이터 갱신 시 간선 색인과 기존 노드 순회·화면 내 요소 그리기 비용은 남는다.

`visibleGraphEdges()`가 기존 렌더러와 동일한 부모·좌표·미조회 점선을 화면 구간으로 제한한다. 해당 기하 정보로 Canvas 선을 그리며, 데이터·뷰포트 변경 때만 같은 곡선의 `Path2D`를 만든다. Hover나 불투명도 프레임에서는 다시 만들지 않는다. 선 판정은 이 화면 구간의 캐시와 경계 상자만 확인한 뒤 `isPointInStroke()`로 실제 곡선 거리를 비교한다. 이벤트 중 Canvas 변환·선 폭 등 상태는 저장·복원해 그리기에 영향을 주지 않는다.

- Hover마다 DAG 레이아웃을 재계산하거나 앱 전체 상태를 갱신하지 않는다.
- HEAD·부모·참조 변경과 추가 로딩 시 기존 데이터로 흐름을 다시 계산한다. 삭제된 배지나 없는 커밋은 해제한다.
- 미조회 부모는 기존 점선 간선만 포함하고 하이라이트를 위해 이력을 조회하지 않는다.
- API·인증·ETag·캐시·자동 갱신 주기·Job 데이터와 URL·PWA·배포 설정·버전은 변경하지 않는다.
- 주기 타이머·의존성·UI 설정을 추가하지 않는다. 빈틈 해제용 취소 가능한 100ms 단발 예약은 그래프당 최대 하나다.

- 기준 HEAD를 작업으로 가져오는 동기화 병합, 여러 작업이 같은 기준 HEAD를 가져오는 경우, 첫 번째 부모 연속을 일반/병합 커밋에서 일관되게 처리하는 회귀를 검증했다. 수정 전 새/수정 테스트 중 3개가 실패했고 수정 후 흐름 테스트 25개와 전체 459개·Production 빌드가 통과했다. 기준 이름을 `main`과 `release/custom`으로 바꿔도 같은 규칙을 적용했다.
- 로컬 Chromium의 1440px·390px 일반 화면과 780px 2열에서 동기화 전용/실제 작업 통합 후 6가지 조건을 확인했다. 기준 흐름에 거짓 종료가 없고 작업의 실제 종료 노드·정확한 연결선은 유지됐다. Hover 추가 API 요청·DAG 레이아웃 호출은 각각 0회였다.
- 실제 Git 사례의 `373287d → 24c26bf → 364ac3e`는 기준 브랜치를 바꾼 단위 재구성과 7가지 일반/분할/터치 화면에서 그대로 유지됐다. Safari·실기기/PWA는 미확인이다.
