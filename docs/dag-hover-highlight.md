# Commit Trail — Git DAG 경로 색상과 하이라이트

## 목적과 공통 정책

브랜치가 어디에서 시작해 어떤 커밋을 거쳐 어디로 병합됐는지, 화면에 표시된 흐름의 시작과 끝을 함께 따라가도록 한다. 색상과 하이라이트는 **같은 경로 ID와 첫 번째 부모 경계**를 사용한다. 팔레트 색이 우연히 같다는 이유로 다른 경로를 함께 강조하지 않는다.

- 브랜치 배지·커밋 노드·보이는 메시지의 Hover와 커밋 노드·메시지의 클릭·탭은 해당 경로 전체와 시작·종료 경계를 강조한다. 브랜치 배지는 정보 표시용이며 클릭·탭으로 커밋을 선택하지 않는다.
- 첫 번째 부모선은 자식 경로, 두 번째 이후 부모의 병합선은 유입 부모 경로에 속한다. 병합선 Hover는 그 유입 부모까지의 경로와 선택한 병합점을 표시한다.
- 넓은/좁은 일반 화면과 모든 Split view 열에 같은 정책을 적용한다. 너비와 포인터 종류는 배치·Hover 가능 여부에만 사용한다.
- 기존 Canvas 2D, 실제 레인·31px 행 간격·배지 배치·클릭 영역·Actions 상태·상세 팝업은 유지한다. 하이라이트를 위한 API 요청을 추가하지 않는다.

## 경로 소유권

경로를 차지하는 순서와 이후 색상 충돌을 보정하는 순서는 구분한다. 공통 경로 인덱스는 다음 순서로 첫 번째 부모 경로를 고정한다.

1. 선택한 기준 HEAD
2. 저장소 메타데이터가 알려주는 기본 브랜치 HEAD
3. 로딩된 첫 번째 부모 자식이 없는 일반 참조 HEAD 중 자신의 첫 부모 줄기에서 다른 경로를 병합받은 근거가 있는 통합 브랜치
4. 통합 근거가 같은 일반 끝점끼리는 분기 뒤 첫 커밋 시각이 이른 순서, 동률은 HEAD SHA 순서

기준·기본 HEAD는 첫 부모 자식이 있어도 먼저 보호한다. 기본 HEAD가 이미 기준 경로에 포함됐다면 기준 경로의 소유권을 유지하며 그 위치에서 다시 나누지 않는다. 따라서 기본 HEAD에서 새 작업 브랜치가 갈라져 아직 기본 브랜치가 진행하지 않은 경우에도 작업 브랜치가 기본 이력을 가져가지 않는다. 일반 참조에만 끝점 조건을 적용하고, 같은 통합 우선순위 안에서는 아래의 첫 커밋 시각·HEAD SHA 순서로 정렬한다. 같은 SHA의 참조는 한 후보로 묶으며, 두 번째 이후 부모로 병합됐다는 이유로 끝점에서 제외하지 않는다. 아직 주인이 없는 이름 없는 경로는 그 뒤에 정규화한 DAG의 위상 순서로 배정한다. 순회는 다른 경로가 차지한 첫 노드에서 멈추고, 강조할 때 그 노드를 시작 경계로 포함한다. 중간 참조는 별칭으로만 연결하므로 이름 없는 과거 경로의 중간에 참조가 생겨도 경로를 나누지 않는다.

통합 근거는 끝점에서 가장 가까운 로딩된 첫 부모 분기·기준/기본선 합류까지의 고유 구간에서만 찾는다. 물려받은 공통 조상의 병합은 근거가 아니다. 두 번째 이후 부모가 로딩된 다른 경로에 속해야 하며, 이미 첫 부모 조상에 포함된 중복 부모나 확인된 기준·기본 브랜치를 받아온 동기화는 제외한다. 이름이나 HEAD 최신 시각으로 통합 브랜치를 추정하지 않는다.

같은 통합 우선순위의 끝점은 고유 구간에서 **위상상 가장 오래된 첫 부모 커밋**을 찾아 그 커밋의 `commitTime()`이 이른 쪽부터 처리한다. 모든 커밋 시각의 최솟값이나 최신 HEAD 시각을 고르는 것이 아니다. `commitTime()`은 유효한 커미터 시각을 우선하고 없거나 잘못됐으면 작성자 시각을 사용한다. 둘 다 없거나 잘못되면 알려진 시각보다 뒤에 놓고, 시각이 같거나 모두 미상일 때는 HEAD SHA로 정한다.

Git 커밋은 실제 브랜치 생성·수명·병합 의도를 기록하지 않는다. 부분 로딩이나 알려지지 않은 동기화 때문에 통합 근거가 없거나 모호할 수 있다. 이때는 이름을 추측하거나 API를 추가 호출하지 않고 알려진 첫 커밋 시각과 SHA 순서로 처리한다. Rebase·커밋 시각 오류·더 오래된 페이지 로딩으로 고유 구간이나 그 시각이 달라지면 소유권 우선순위도 바뀔 수 있다. 따라서 모든 임의 이름·불완전 이력에서 원래 줄기의 의도를 복원한다고 보장하지 않는다. 기준 브랜치 선택의 기존 `main` → `master` → 저장소 기본 브랜치 정책과 이 경로 소유권 순서는 별개다.

`dev=a4 → a3 → a2 → a1`에서 `feature=f2 → f1 → a3`가 더 최근인 회귀 사례를 검증한다. 고유 구간의 첫 커밋인 `a4`의 시각이 `f1`보다 이른 이 사례에서 `dev`는 `a1~a4`, `feature`는 `f1,f2`와 시작 경계 `a3`까지만 표시한다. `topic=a2`는 `dev` 경로의 별칭이다. 40자리 무작위 SHA로도 같은 회귀를 검증하며, 이 결과는 `dev`라는 이름이나 축약 SHA의 우연한 사전순을 특별 취급한 것이 아니다.

## 결정적 색상 배정

색은 localStorage나 탭에 남은 이전 색(`previous`) 없이 현재 데이터에서 계산한다. **같은 참조 목록·같은 로딩 범위·같은 기준 브랜치와 HEAD SHA·같은 저장소 기본 브랜치 정보**라면 자동 갱신·브라우저 새로고침·서로 다른 브라우저 컨텍스트에서 같은 팔레트 번호를 사용한다. 입력 배열의 도착 순서, 기존 레인 배치, 화면 너비·방향·테마는 배정 근거가 아니다. 밝은/어두운 테마는 같은 번호에 대응하는 각 테마의 색을 사용한다.

1. SHA 기준으로 정규화한 DAG와 이전 레인 배정을 사용하지 않은 기준 배치에서 경로 및 인접 관계를 구한다. 이 계산은 색상 판단용이며 실제 화면의 레인 위치를 바꾸지 않는다.
2. 기준 경로를 먼저 배정하고 나머지는 각 경로가 소유한 가장 오래된 로딩 커밋의 SHA 순서로 처리한다. 같은 시작 SHA에서는 HEAD SHA로 순서를 정한다. 이 시작은 현재 데이터에서 확인한 위치이며 정확한 브랜치 생성점은 아니다. 과거 페이지가 더 오래된 시작을 드러내면 우선순위가 달라질 수 있다. 이름순 도착이나 브라우저 저장 상태에 우선권을 주지 않는다.
3. 기준 경로는 기존 0번 색을 사용한다. 나머지는 경로 HEAD에 참조 이름이 있으면 전체 브랜치 이름의 해시를 기본 색으로 사용한다. 같은 HEAD의 별칭은 이름의 코드 단위 순서로 대표를 고른다. HEAD에 이름이 없으면 해당 HEAD SHA의 해시를 사용한다. 중간 참조만 있는 경로도 SHA를 사용해 별칭 추가가 기존 경로를 다시 구분하지 않게 한다.
4. 기본 색이 이미 배정된 인접 경로와 겹치면 1~7번을 기본 색부터 순환하고 마지막에 0번을 후보로 확인한다. 8색을 모두 피할 수 없는 경우에는 충돌이 가장 적은 후보를 결정적으로 고른다. 동일 색의 재사용 자체를 경로 합침으로 취급하지 않는다.

기존 6색에 분홍·라임을 추가해 총 8색을 사용한다. 추가 색은 밝은/어두운 그래프 배경과 실제 반투명 배지 배경에서 텍스트 대비 4.5:1 이상을 만족하도록 검증한다. 기존 6색은 유지한다.

### 색상 유지의 범위

저장소 상태가 같을 때의 재현성을 보장한다. 새 브랜치·참조·기본 브랜치 정보가 생기거나 과거 이력을 더 불러와 경로 경계·통합 근거·이웃 구성이 달라지면 충돌 보정 결과가 달라질 수 있다. 분기점이나 HEAD가 달라져 이름 없는 경로 ID가 바뀌는 경우도 재계산한다. 이를 막기 위해 이전 탭의 배정을 유지하지 않는다. 따라서 서로 다른 로딩 범위나 참조 상태 사이의 색상 불변성, 모든 인접 경로의 무조건적인 색상 분리는 보장하지 않는다.

자동 갱신·브라우저 새로고침·과거 이력 추가·새 브랜치 등장 각각에서 최종 데이터가 같은 두 새 컨텍스트의 결과를 비교한다. 최종 데이터가 달라진 경우에는 경로/이웃 변경에 따른 차이와 같은 상태에서 발생한 비결정적 차이를 구분한다.

## 강조 범위

### 브랜치 이름·커밋·메시지

경로의 HEAD부터 첫 번째 부모를 따라 같은 경로 ID의 노드·연결선을 표시한다. 다른 경로와 만나는 첫 노드는 시작 경계로 포함하되 그 이전 공통 이력은 따라가지 않는다. 중간 커밋을 대상으로 하더라도 같은 경로의 HEAD 쪽과 시작 경계를 함께 보여준다.

- 중간 커밋을 가리키는 별도 참조가 있어도 같은 색상 경로를 임의로 나누지 않는다. `dev=a4`의 경로 중간에 `topic=a3`가 남아 있어도 `a3`에서 끊지 않는다.
- 같은 HEAD를 가리키는 이름 배지들은 각각 유지한다. 명시적으로 Hover한 이름만 선명하게 표시하고 다른 이름을 임의로 선택하지 않는다.
- 시작 경계 노드 자체를 선택하면 그 노드가 실제로 속한 경로를 표시한다. 경계로 포함됐다는 이유로 자식 경로를 모두 강조하지 않는다.
- 삭제된 브랜치 이름은 복원하거나 추측하지 않는다. 이름 없는 과거 구간도 동일한 경로 ID로 색상과 강조를 판정한다.
- 시작점은 현재 조회된 DAG에서 확인한 경계이다. 미조회 구간을 실제 루트나 정확한 브랜치 생성 시점으로 단정하지 않는다.
- 숨겨진 메시지에는 별도 Hover·클릭 영역을 만들지 않는다.

### 연결선 Hover

- 포인터가 실제 Canvas 곡선에서 5 CSS px 이내에 있으면 해당 선을 Hover 대상으로 삼는다. 방향 반전·스크롤·DPR 변경·좁은 열에서도 같은 그래프 좌표를 사용한다.
- 첫 번째 부모선은 기본적으로 자식 경로 전체를 강조한다. 병합선은 유입 부모부터 **그 부모가 속한 색상 경로의 시작 경계까지** 따라가고 선택한 병합 노드·정확한 연결선을 포함한다. 해당 병합 뒤의 유입 경로 작업과 다른 병합점은 포함하지 않는다.
- 이전 승격에 이미 포함된 커밋이라는 이유로 같은 색상 경로의 중간에서 멈추지 않는다. `e1ac3b8 → a4304a2`가 dev 유입선이라면 `a4304a2`에서 dev 경로의 시작 경계까지 표시하며 현재 dev HEAD 쪽의 이후 커밋은 제외한다.
- 배지는 실제 참조 HEAD가 강조 범위에 있으면서 같은 유입 경로에 속하는 경우에 표시한다. 시작 경계의 다른 경로 배지는 포함하지 않는다. 과거 유입 커밋 이후로 진행된 현재 브랜치 이름을 과거 커밋의 이름으로 오인하게 표시하지 않는다.
- 병합선을 가리킨 뒤 강조 중인 첫 부모선으로 이동하면 해당 병합 시점의 범위를 유지한다. 노드·배지·보이는 메시지는 자체 판정이 우선한다. 기존 커밋이 선택돼 있어도 병합선 Hover가 임시 우선하며 이탈하면 선택 흐름으로 복귀한다.
- 노드·배지·메시지 판정을 먼저 적용한다. 겹치는 선 중에서는 실제 곡선에 더 가까운 선을 고르고 거리 차이가 0.5px 이하이면 현재 강조 흐름을 유지한다. 기존 강조가 없고 다른 흐름의 선을 구분할 수 없는 교차점에서는 임의로 하나를 고르지 않는다.
- 미조회 첫 부모의 점선은 알려진 자식 경로에 연결한다. 미조회 병합 부모는 임의의 경로로 연결하거나 추가 조회하지 않는다.
- 선 Hover는 선택·상세 조회를 시작하지 않는다. 별도 선 클릭·탭 동작을 추가하지 않고 노드의 클릭·탭 영역과 터치 스크롤을 유지한다.

### 종료 경계와 판정 한계

경로 HEAD를 두 번째 이후 부모로 받아들이는 다른 경로의 병합 노드와 정확한 연결선을 종료 경계로 표시한다. 종료 노드의 다른 부모·후속 이력으로 확장하지 않는다. 첫 번째 부모 연속과 단순 한 부모 분기는 종료가 아니다. 중간 작업만 병합된 뒤 경로가 계속됐다면 그 과거 병합은 현재 전체 경로의 종료점이 아니다.

현재 기준 HEAD의 경로는 종료 판정에서 제외한다. 기준 흐름을 받아온 동기화 병합이 기준 흐름을 끝낸 것으로 표시되는 것을 피하기 위한 규칙이며 특정 브랜치 이름에 의존하지 않는다. 동일 HEAD를 여러 경로에서 병합했다면 조회된 종료점들을 각각 표시한다. 아직 병합되지 않았거나 종료 커밋이 미조회 상태면 현재 HEAD까지만 표시한다.

종료 판정은 조회된 부모 관계와 기준 경로에 따른 휴리스틱이며 실제 브랜치 생성·삭제·통합 완료를 확정하지 않는다. 기준이 아닌 경로를 받아온 동기화가 종료로 표시될 수 있고 기준 경로 자체의 실제 승격은 종료 표시에서 제외될 수 있다. 이 의도를 추측하기 위한 이름 하드코딩이나 추가 API 요청은 하지 않는다.

## 불투명도

| 요소                           | 대상      | 비대상         |
| ------------------------------ | --------- | -------------- |
| 노드·메시지                    | 기존 100% | 25%            |
| 연결선·배지·SHA·작성자         | 기존 값   | 기존 값 × 0.25 |
| Actions 도넛·진행률 호·회전 링 | 기존 값   | 기존 값 × 0.25 |
| 태그·릴리즈 아이콘             | 기존 100% | 25%            |

Actions는 상태 색상·선 두께·반지름·Job 완료율과 회전 시작 시각을 유지한다. 진행 배경의 0.25, 대기·취소·건너뜀의 0.4에도 비대상 배율을 상대적으로 곱한다. Job 수 미확정 DOM 회전 링도 같은 정책을 사용한다.

태그·릴리즈 아이콘은 연결된 커밋 노드의 불투명도를 함께 사용하며, 강조가 해제되면 기존 밝기로 돌아온다.

기존 선택 노드 크기와 상세 정보, 말줄임된 이름의 전체 툴팁·위치·개별 배지·충돌 회피는 유지한다.

대상이 바뀌거나 강조가 해제되면 불투명도만 약 140ms 동안 부드럽게 전환한다. 도중에 다른 대상으로 이동하면 현재 표시 중인 값에서 새 목표로 이어지며, 전체 밝기로 초기화하지 않는다. 노드·메시지·연결선·배지·태그/릴리즈 아이콘과 Canvas/DOM Actions 링은 같은 시간과 보간 배율을 사용한다. 새 설정이나 토글은 추가하지 않는다.

## 입력과 수명

- `(any-hover: hover)`를 지원하는 포인터는 마우스 이동으로 임시 강조한다. Hover만으로 선택하거나 상세를 조회하지 않는다.
- 클릭·탭은 기존 상세와 함께 선택 흐름을 표시한다. Hover는 선택보다 임시 우선하며, Hover 해제 후에는 유효한 선택 흐름으로 돌아간다.
- 커밋 사이의 빈틈에서는 최대 100ms 이전 Hover를 유지해 전체 밝기로 깜빡이지 않게 한다. 새 대상은 즉시 전환 목표로 적용하고 이전 해제 예약을 취소한다. 같은 대상 재진입도 예약을 취소하며, 반복 빈 공간 이동으로 기한을 연장하지 않는다.
- 그래프 이탈·스크롤·blur·크기/열 순서 변경은 Hover 대상을 즉시 해제하고 불투명도는 유효한 선택 또는 기본값으로 전환한다. 클릭·터치·종료·언마운트도 해제 예약을 정리해 늦은 콜백이 새 흐름을 지우지 않게 한다.
- 상세 닫기·빈 공간 클릭/탭·다른 저장소 선택 등으로 기존 선택이 해제되면 선택 강조도 해제한다. 선택이 유지되는 크기·순서 변경에서는 유효한 흐름을 유지한다.
- 터치 시작·스와이프·롱 프레스·취소된 포인터만으로 새 선택을 만들지 않는다. 기존 터치 스크롤을 유지한다.
- 각 Graph가 독립 처리한다. 같은 SHA를 가진 다른 저장소나 다른 Split view 열을 흐리게 만들지 않는다.

## 구현과 성능

색상 계산에서 만든 공통 경로 인덱스를 노드·간선 색상, `branchTracks()`와 `graphHoverIndex()`가 함께 사용한다. 경로 ID는 현재 스냅샷의 경로 HEAD SHA이며, 명시적 병합 강조는 병합 커밋·유입 부모 SHA 쌍으로 구분한다. 팔레트 번호·레인·좌표는 경로 식별자가 아니다. 중간 참조를 별도 경계로 만들지 않으며 같은 팔레트 번호가 재사용돼도 서로 다른 ID의 경로를 합치지 않는다.

`resolveGraphHover()`는 배지·커밋 Hover와 선택에 같은 경로 결과를 제공하고 최근 두 결과만 캐시한다. 병합선 결과도 같은 캐시를 사용하며 유입 부모에서 같은 경로 ID를 따라 시작 경계까지만 순회한다. 목적지의 과거 병합 조상을 탐색해 이번 승격분을 따로 구하지 않는다. 같은 경로 내 이동은 결과를 재사용하고 하이라이트를 위한 이력 요청은 만들지 않는다.

`GraphOpacity`는 비대상 공통 불투명도와 개별 예외의 시작값·목표값으로 140ms smoothstep 보간을 계산한다. 대상 변경 시 이전/다음 강조 집합과 전환 중인 예외만 순회하며 A→B→C 이동 중인 이전 A의 표시값도 보존한다. 기존 노드·간선·참조 Map의 `has`·`size`를 재사용해 전체 요소 집합을 복제하거나 순회하지 않는다. 새 비대상 요소는 현재 공통 불투명도로 표시하며 삭제·완료된 예외는 정리한다.

전환 중에만 `requestAnimationFrame`으로 다시 그리며 완료 후 중단한다. 프레임마다 React 상태나 DAG 레이아웃을 갱신하지 않는다. DOM 회전 링도 Canvas와 같은 프레임의 불투명도를 적용하고 회전은 다시 시작하지 않는다. 동등한 데이터·결과는 전환 기한을 연장하지 않는다. 비활성화·언마운트·그리기 효과 교체 시 이전 프레임을 취소한다.

`visibleGraphEdges()`는 화면 구간의 기존 곡선 기하 정보를 그리기와 `Path2D` 판정에 재사용한다. 데이터·뷰포트 변경 때만 경로를 만들고 Hover·전환 프레임에서는 다시 만들지 않는다. 경계 상자와 `isPointInStroke()`로 곡선 거리를 비교하며 Canvas 상태를 저장·복원한다.

- 현재 데이터가 바뀌면 경로·색상·인접 관계를 결정적으로 재계산한다. Hover마다 재계산하지 않는다.
- API·인증·ETag·캐시·자동 갱신 주기·Job 데이터·URL·PWA·배포 설정·버전은 변경하지 않는다.
- 주기 타이머·의존성·저장 키·UI 설정을 추가하지 않는다. 빈틈 해제용 취소 가능한 100ms 단발 예약은 그래프당 최대 하나다.
