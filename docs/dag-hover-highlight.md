# Commit Trail — Git DAG 브랜치 흐름 하이라이트

## 목적과 공통 정책

브랜치가 어디에서 시작해 어떤 커밋을 거쳐 어디로 병합됐는지, 화면에 표시된 흐름의 시작과 끝을 함께 따라가도록 한다.

- 브랜치 이름 Hover와 커밋 노드·보이는 메시지의 Hover·클릭·탭은 같은 흐름 판정을 사용한다.
- 해당 흐름의 첫 번째 부모(`parents[0]`) 연결·시작 경계와 HEAD를 받아들이는 종료 병합·연결선을 강조한다. 두 경계 너머의 조상 전체·다른 병합 부모·후속 이력으로 확장하지 않는다.
- 넓은/좁은 일반 화면과 모든 Split view 열에 같은 정책을 적용한다. 너비와 포인터 종류는 배치·Hover 가능 여부에만 사용한다.
- 기존 Canvas 2D, 레인·색상·31px 행 간격·배지 배치·클릭 영역과 상세 팝업을 유지한다.

## 강조 범위

### 브랜치 이름

실제 참조 HEAD에서 그 브랜치의 흐름을 따라간다. 시작 쪽에서는 다른 흐름과 만나는 노드와 그 노드까지의 연결선을 포함하고 그 이전 공통 이력은 흐리게 표시한다. 종료 쪽에서는 HEAD를 받아들이는 병합 커밋과 정확한 연결선을 포함하고 그 커밋의 다른 이력은 따라가지 않는다.

같은 HEAD를 가리키는 이름 배지들은 각각 유지한다. 명시적으로 Hover한 이름만 선명하게 표시하고 다른 이름을 임의로 선택하지 않는다.

### 커밋 노드·메시지·선택

중간 커밋을 대상으로 하더라도 해당 흐름 전체와 양쪽 경계를 표시한다. 같은 흐름의 HEAD 쪽 커밋·시작 경계·종료 병합을 함께 보여주므로 노드 사이를 이동해도 강조 범위가 바뀌지 않는다.

- 알려진 다른 HEAD를 만나거나 이미 다른 흐름이 차지한 첫 번째 부모에 도달하면 경계로 포함하고 종료한다.
- 시작 또는 종료 경계 노드 자체를 선택하면 그 노드가 실제로 속한 흐름을 표시한다. 자식 브랜치가 경계를 포함했다는 이유로 그 자식 흐름들을 모두 강조하지 않는다.
- 브랜치 이름이 삭제된 과거 커밋도 로딩된 DAG의 첫 번째 부모 관계로 흐름을 찾는다. 이름을 복원하거나 새 이름을 추측하지 않는다.
- 시작점은 현재 조회된 DAG에서 확인한 분기·공유 HEAD 경계이다. 미조회 구간을 실제 루트나 정확한 브랜치 생성 시점으로 단정하지 않는다.
- 숨겨진 메시지에는 별도 Hover·클릭 영역을 만들지 않는다.

### 병합

통합 브랜치 내부에서는 병합 커밋과 첫 번째 부모를 잇는 주 흐름을 강조하고, 병합으로 들어온 다른 작업 브랜치와 그 연결선은 흐리게 표시한다. 통합 흐름의 현재 HEAD가 다른 흐름으로 병합된 종료 경계에는 아래와 같은 공통 규칙을 적용한다.

작업 브랜치에서는 그 작업 흐름과 시작 경계, 종료 병합 커밋과 `종료 병합 → 흐름 HEAD` 연결선을 강조한다. 종료 커밋의 다른 부모·후속 커밋·다른 병합 브랜치는 제외한다.

- 종료 병합은 부모가 둘 이상이고 해당 흐름의 HEAD를 실제 부모로 가지며, 다른 흐름에 속하는 커밋이다. HEAD가 첫 번째 부모인 경우도 포함하고, 부모가 하나뿐인 단순 분기는 종료 병합으로 취급하지 않는다.
- HEAD가 아닌 중간 커밋만 병합된 뒤 작업이 계속됐다면 그 과거 병합은 현재 흐름의 종료점으로 표시하지 않는다.
- 동일 HEAD를 여러 흐름에 병합했다면 조회된 종료점들을 각각 표시하되 그 너머로는 확장하지 않는다. 이는 관찰된 병합 경계이며 브랜치가 삭제됐다는 의미는 아니다.
- 아직 병합되지 않았거나 종료 커밋이 미조회 상태면 현재 HEAD까지 표시한다. 종료점을 찾기 위한 추가 요청은 하지 않으며 새 데이터가 도착하면 기존 인덱스를 다시 계산한다.

### 예시

- `merge`의 부모가 `base, feature`이고 `feature → base → root`라면, 작업 흐름은 `merge(종료) → feature → base(시작)`이다. `base → root`, `merge → base`는 비대상이며 종료 병합의 다른 이력으로 확장하지 않는다.
- `d4 → d3 → d2 → d1`에서 `dev=d4`, `main=d2`이면 `dev` 흐름은 `d4,d3,d2`이며 `d1`은 제외한다. `main` 흐름은 `d2,d1`이다. `d3` Hover·선택도 `dev` 배지와 같은 흐름을 표시한다.
- 첨부 사례의 `24c26bf`는 `364ac3e`에서 시작해 `373287d`로 병합된 작업 흐름이다. `373287d → 24c26bf → 364ac3e`와 양쪽 경계 노드는 포함하지만 `99d783d`, `8c2c0ee`, `25069fd` 등 이전·병합 이력은 따라가지 않는다.

## 불투명도

| 요소 | 대상 | 비대상 |
| --- | --- | --- |
| 노드·메시지 | 기존 100% | 25% |
| 연결선·배지·SHA·작성자 | 기존 값 | 기존 값 × 0.25 |
| Actions 도넛·진행률 호·회전 링 | 기존 값 | 기존 값 × 0.25 |
| 태그·릴리즈 아이콘 | 기존 값 | 기존 값 |

Actions는 상태 색상·선 두께·반지름·Job 완료율과 회전 시작 시각을 유지한다. 진행 배경의 0.25, 대기·취소·건너뜀의 0.4에도 비대상 배율을 상대적으로 곱한다. Job 수 미확정 DOM 회전 링도 같은 정책을 사용한다.

기존 선택 노드 크기와 상세 정보, 말줄임된 이름의 전체 툴팁·위치·개별 배지·충돌 회피는 유지한다.

## 입력과 수명

- `(any-hover: hover)`를 지원하는 포인터는 마우스 이동으로 임시 강조한다. Hover만으로 선택하거나 상세를 조회하지 않는다.
- 클릭·탭은 기존 상세와 함께 선택 흐름을 표시한다. Hover는 선택보다 임시 우선하며, Hover 해제 후에는 유효한 선택 흐름으로 돌아간다.
- 커밋 사이의 빈틈에서는 최대 100ms 이전 Hover를 유지해 전체 밝기로 깜빡이지 않게 한다. 새 대상은 즉시 적용하고 이전 해제 예약을 취소한다. 같은 대상 재진입도 예약을 취소하며, 반복 빈 공간 이동으로 기한을 연장하지 않는다.
- 그래프 이탈·스크롤·blur·크기/열 순서 변경은 즉시 Hover를 해제한다. 클릭·터치·종료·언마운트도 해제 예약을 정리해 늦은 콜백이 새 흐름을 지우지 않게 한다.
- 상세 닫기·빈 공간 클릭/탭·다른 저장소 선택 등으로 기존 선택이 해제되면 선택 강조도 해제한다. 선택이 유지되는 크기·순서 변경에서는 유효한 흐름을 유지한다.
- 터치 시작·스와이프·롱 프레스·취소된 포인터만으로 새 선택을 만들지 않는다. 기존 터치 스크롤을 유지한다.
- 각 Graph가 독립 처리한다. 같은 SHA를 가진 다른 저장소나 다른 Split view 열을 흐리게 만들지 않는다.

## 구현과 성능

`graphHoverIndex()`가 렌더러의 위상 순서, 실제 첫 번째 부모와 참조 HEAD로 노드의 흐름 소유자를 계산한다. 기준 HEAD, 알려진 HEAD, 이름 없는 나머지 경로 순서로 각 노드를 한 번씩 배정하며 다른 알려진 HEAD를 넘어 차지하지 않는다. 병합 부모 관계도 한 번 인덱싱해 각 흐름 HEAD를 받아들이는 종료 병합만 기록한다.

흐름 식별자는 SHA이고 색상 값·레인 번호·좌표가 아니다. 같은 색이 재사용되거나 같은 레인에 있어도 다른 경로를 합치지 않는다. `branchTracks()`는 이름과 HEAD의 연결에 재사용하며, 배지 배치 자체는 변경하지 않는다.

`resolveGraphHover()`가 배지·커밋 Hover와 선택에 같은 흐름 결과를 제공한다. 최근 두 흐름만 캐시하고, 한 흐름의 여러 커밋과 선택은 같은 결과를 재사용해 불필요한 Canvas 다시 그리기를 피한다.

- Hover마다 DAG 레이아웃을 재계산하거나 앱 전체 상태를 갱신하지 않는다.
- HEAD·부모·참조 변경과 추가 로딩 시 기존 데이터로 흐름을 다시 계산한다. 삭제된 배지나 없는 커밋은 해제한다.
- 미조회 부모는 기존 점선 간선만 포함하고 하이라이트를 위해 이력을 조회하지 않는다.
- API·인증·ETag·캐시·자동 갱신 주기·Job 데이터와 URL·PWA·배포 설정·버전은 변경하지 않는다.
- 주기 타이머·의존성·UI 설정을 추가하지 않는다. 빈틈 해제용 취소 가능한 100ms 단발 예약은 그래프당 최대 하나다.

기존 테스트를 현재 정책에 맞춰 수정하고 관련 회귀 시나리오를 검증한다.

- 양쪽 경계 포함·공통 이력 제외, 중간 커밋의 전체 흐름, 통합/작업 브랜치 분리, 다중 종료·첫 번째 부모 종료·중간 작업 병합 제외·종료점 추가 로딩
- 삭제된 브랜치 이름, 같은 HEAD 별칭, 같은 줄기의 서로 다른 참조 HEAD, 다중 부모
- 동일 색상·동일 좌표에서도 경로 분리, 미조회 점선 경계, HEAD 변경·참조 삭제·추가 로딩
- 방향 반전·Hover/선택 공통 판정, 같은 흐름의 캐시 재사용·두 항목 제한, 10,000개 커밋 반복 순회
- 실제 `24c26bf` 사례의 시작·종료 경계와 그 너머 다른 색상 이력 제외
- 넓은/좁은 일반 화면·Split view·터치, Actions 불투명도·아이콘·툴팁·선택·상세 유지
- 빈틈 전환과 예약 취소, 스크롤·크기 변경·종료, 추가 API 요청·DAG 레이아웃 호출 부재

검증 결과와 브라우저·실기기 한계는 PR에 기록한다. `AGENTS.md`에 따라 검증 후 `dev` 대상 PR을 갱신하며, 별도 요청 없이 병합·Production 배포를 수행하지 않는다.

### 현재 검증 결과

- 흐름 테스트 22개와 전체 소스 테스트 **456개**, TypeScript 검사·Production 빌드·포맷·diff 검사가 통과했다.
- 실제 저장소의 150개 커밋 스냅샷에서 `main` 또는 작업 브랜치를 기준으로 계산해도 `24c26bf`의 흐름은 양쪽 경계를 포함한 `373287d → 24c26bf → 364ac3e`였다. 양쪽 경계 너머의 공통·병합 이력은 포함하지 않았다.
- 이 실제 Git 데이터를 로컬 응답으로 재구성한 Chromium의 밝은/어두운 1440px 일반 화면, 390px 일반 화면, 1440·780px 2열과 터치 등 7가지 조건에서 같은 범위·선택/상세·해제·독립 열을 확인했다. Hover 추가 API 요청과 DAG 레이아웃 호출은 각각 0회였다.
- 별도 9가지 합성 조건에서 25% 도넛 배율·상태/진행률·회전 유지·아이콘 보존, 같은 흐름 안에서 Canvas 재그리기 0회, 짧은 빈틈과 해제 예약 취소를 확인했다. 좁은 390px·2열·8열·reduced motion·터치와 Job 수 확정/미확정 조건을 포함한다.
- Safari·모바일 실기기/PWA 및 실제 GitHub 응답 지연은 확인하지 않았다. 로컬 재구성 응답 검증이 해당 환경의 검증을 대신하지 않는다.

- 종료 경계 추가 후 실제 Git 스냅샷의 `373287d → 24c26bf → 364ac3e`와 두 연결선을 7가지 일반/분할/터치 조건에서 확인했다. 별도 마우스·터치 조건에서 종료 병합의 도넛도 대상 배율을 유지하고 다른 부모·후속 이력은 흐리며, 같은 흐름 재사용과 상세 닫기 복원이 유지됨을 확인했다. 전체 456개 테스트와 Production 빌드가 통과했다.
