# Commit Trail — Git DAG Hover 하이라이트 개발 명세

## 1. 작업 목적

Commit Trail의 Git DAG에서 브랜치 이름 Hover는 해당 HEAD, 커밋 Hover·클릭·탭은 해당 커밋을 시작점으로 모든 부모의 조상 이력을 강조합니다. 모든 화면과 입력에서 같은 부모 관계 판정을 사용합니다.

복잡한 분기·병합 그래프에서 관심 없는 경로를 흐리게 표시하여, 사용자가 원하는 브랜치의 변화와 작업 내용을 쉽게 파악하는 것이 목적입니다.

### 기본 원칙

- 기존 Canvas 2D 렌더러 재사용
- 화면 너비·일반/Split view·입력 방식에 관계없는 공통 커밋 조상 강조
- 브랜치 경로·커밋 노드·메시지를 함께 강조
- 다른 경로의 불투명도 25%
- Git DAG의 실제 부모 관계 존중
- 기존 레인·색상·정렬·스크롤 정책 유지
- 새로운 GitHub API 요청 및 UI 설정 추가 금지
- 일반 화면과 Split view에 동일한 동작 적용

## 2. Hover 대상

### 2.1 브랜치 이름 배지

브랜치 이름 배지에 마우스를 올리면 해당 브랜치를 강조합니다.

- 브랜치 HEAD에서 모든 부모를 따라간 실제 조상 이력을 대상으로 합니다. 첫 번째 부모뿐 아니라 병합된 작업 커밋과 합류 이후 공통 이력을 포함합니다.
- 해당 조상 범위의 실제 부모 연결선·커밋 노드·메시지·도넛을 강조합니다. HEAD보다 새로운 자손이나 별도 릴리즈 커밋은 포함하지 않습니다.
- 다른 경로는 불투명도를 25%로 낮춥니다.
- 기존 브랜치 전체 이름 툴팁은 유지합니다.
- 동일 HEAD의 여러 이름 중 Hover한 배지 이름만 선명하게 표시합니다. 조상 범위 안에 HEAD가 있는 이전 브랜치의 이름도 선명하게 유지하되, 새로운 자손이나 조상이 아닌 형제 릴리즈의 이름은 포함하지 않습니다.

### 2.2 커밋 노드

커밋 노드에 마우스를 올리거나 클릭·탭하면 해당 커밋과 **모든 부모를 따라간 조상 이력**을 강조합니다.

- 병합으로 들어온 브랜치와 합류 이후의 공통 이력을 포함합니다.
- 현재 커밋보다 새로운 자손과 관련 없는 분기는 강조하지 않습니다.
- 같은 HEAD·공유 커밋도 실제 부모 관계를 사용하며 임의로 특정 브랜치를 선택하지 않습니다.
- 넓은/좁은 일반 화면과 모든 Split view 열이 같은 판정과 렌더링을 사용합니다. 마우스 Hover·클릭과 터치 탭의 강조 범위도 같습니다.
- 브랜치 이름이나 레인 색상으로 조상을 추정하지 않으며 미조회 이력을 추가 요청하지 않습니다.

### 2.3 커밋 메시지

커밋 메시지 Hover는 해당 커밋 노드 Hover와 동일하게 처리합니다.

- 메시지와 노드가 같은 하이라이트 대상을 사용합니다.
- 커밋 메시지가 화면 너비에 따라 숨겨진 경우 별도의 Hover 영역을 만들지 않습니다.
- 기존 클릭·탭으로 커밋 상세를 여는 동작을 유지하며 6절의 공통 선택 강조도 함께 적용합니다.

### 2.4 빈 공간

그래프 안의 빈 공간에서는 최대 100ms 뒤 Hover를 해제하고, 그래프 밖으로 나가면 즉시 해제합니다. 짧은 빈틈을 지나 다른 커밋에 도달하면 이전 해제 예약을 취소하고 새 대상을 즉시 강조합니다.

선택한 커밋이 없으면 Hover 해제 시 모든 요소를 기존 불투명도로 복원합니다. 선택이 남아 있으면 해당 커밋의 조상 강조로 돌아갑니다. 빈 공간 클릭·탭으로 기존 선택이 해제되면 선택 강조도 해제합니다.

## 3. 하이라이트 표시 정책

| 그래프 요소 | 강조 대상 | 비대상 |
|---|---|---|
| 커밋 노드 | 100% | 25% |
| 브랜치 연결선 | 기존 불투명도 유지 | 기존 값의 25% |
| 브랜치 이름 배지 | 기존 표시 유지 | 기존 값의 25% |
| 커밋 메시지 | 100% | 25% |
| SHA·작성자 | 기존 표시 유지 | 기존 값의 25% |
| Actions 도넛 | 기존 불투명도 유지 | 기존 값의 25% |
| 태그·릴리즈 아이콘 | 기존 정책 유지 | 기존 정책 유지 |

### 세부 정책

- 기존 브랜치 색상은 변경하지 않습니다.
- 강조 대상의 선 굵기·노드 크기를 불필요하게 확대하지 않습니다.
- 비대상 요소의 불투명도만 낮춥니다.
- 연결선처럼 기존 불투명도가 적용된 요소는 기존 값에 0.25를 곱해 상대적으로 75% 감소시킵니다.
- Actions 도넛도 해당 커밋의 비대상 배율 0.25를 적용합니다. 기존 상태 색상·선 두께·반지름·Job 진행률은 유지하며 진행 배경 링의 기존 0.25, 대기·취소·건너뜀 링의 0.4에도 상대 배율을 곱합니다. Job 수가 아직 없는 진행 중 DOM 회전 링도 같은 배율을 적용하고 애니메이션을 다시 시작하지 않습니다. 태그·릴리즈 아이콘은 기존 불투명도를 유지합니다.
- 기존 커밋 선택 강조와 Hover 하이라이트는 별도로 유지합니다.

새로운 색상이나 배경 강조 효과는 추가하지 않습니다.

## 4. 브랜치 경로 판정

### 4.1 기존 데이터 활용

현재 구현된 다음 정보를 우선 활용합니다.

- 커밋의 실제 부모 SHA
- `branchTracks()`의 브랜치별 시각적 경로
- `graphColors()`의 노드·간선 색상 정보
- `Graph.tsx`의 커밋 좌표·레인 배치
- 브랜치 이름 배지의 실제 참조 정보

브랜치 색상만 비교하여 동일 경로라고 판단하지 않습니다.

### 4.2 공통 조상 범위

- 브랜치 배지는 실제 HEAD SHA, 커밋 노드·메시지는 해당 SHA를 시작점으로 사용합니다.
- 모든 부모를 재귀적으로 따라가며 병합된 작업 브랜치와 합류 이후의 공통 이력을 포함합니다. 배지 이름 배치를 위한 `branchTracks()`의 first-parent 시각적 경계로 강조 범위를 자르지 않습니다.
- 브랜치 이름 Hover와 같은 HEAD 커밋의 Hover·선택은 노드·간선 범위가 같습니다. 같은 HEAD를 공유한 이름은 명시적으로 Hover한 배지만 구분합니다.
- 새 자손·조상이 아닌 형제 릴리즈·연결되지 않은 이력은 제외합니다. 색상·레인·좌표나 브랜치 이름으로 관계를 추정하지 않습니다.
- 현재 로딩된 커밋만 표시하고 미조회 부모의 기존 점선 간선은 유지합니다. 강조를 위해 추가 요청하지 않으며 새 데이터가 들어오면 실제 부모 범위를 다시 계산합니다.
- 기준 브랜치·일반/좁은 화면·Split view·시간 방향에 관계없이 동일하게 적용합니다.

### 4.3 공유 커밋과 커밋 조상 범위

브랜치 배지 Hover와 커밋 Hover·클릭·탭은 같은 실제 부모 조상 판정을 사용합니다. 시작점만 각각 HEAD 또는 해당 커밋으로 다릅니다.

- 같은 HEAD를 공유하는 이름 배지는 기존 개별 표시와 명시적 브랜치 배지 대상을 유지합니다.
- 커밋이 여러 트랙에 공유되어도 전체 부모 관계는 확정할 수 있으므로, 해당 커밋에서 부모 방향으로만 따라갑니다. 소유 브랜치를 임의로 정하거나 관련 브랜치의 최신 자손까지 확장하지 않습니다.
- 예를 들어 `d4 → d3 → d2 → d1`, 기준 `dev=d4`, `main=d2`에서 `d3` Hover·클릭·탭은 `d3,d2,d1`, `d2`는 `d2,d1`을 강조합니다. 참조 추가·삭제로 커밋 조상 범위가 달라지지 않습니다.
- 선택한 커밋이 속한 기존 트랙의 이름과 조상 범위 안에 HEAD가 있는 이전 브랜치 이름은 선명하게 유지합니다. 여러 이름이 같은 경로를 가리키면 해당 이름들을 유지하며, 이름이 삭제돼도 부모 관계가 남아 있으면 조상 강조는 유지합니다.

이 정책은 최초 버전의 공유 커밋 단독 강조와 브랜치 배지 first-parent 강조 예외를 모두 대체합니다. 모든 진입점은 실제 부모 전체를 사용하며, 명시적인 같은 HEAD의 배지 이름만 구분합니다.

### 4.4 병합 커밋

병합 커밋은 부모가 여러 개일 수 있습니다.

- 브랜치 배지·커밋 Hover·선택 모두 병합의 모든 부모 조상을 포함합니다.
- 다른 부모를 통해 들어오는 병합 연결선은 실제 관계를 유지합니다.
- 하이라이트를 위해 Git DAG 간선이나 레인 배치를 변경하지 않습니다.
- 병합 관계가 불명확한 경우 정확성을 우선하고 무리한 강조를 하지 않습니다.

## 5. 기존 UI와의 연동

### 커밋 상세

- Hover만으로 상세 팝업을 열지 않습니다.
- 기존 클릭·탭으로 상세를 엽니다.
- 상세가 열려 있어도 Hover 하이라이트는 독립적으로 동작합니다.
- 커밋 선택 강조는 기존 정책을 유지합니다.
- Hover가 해제되면 기존 선택 상태와 선택 커밋의 조상 강조로 돌아갑니다. 선택이 해제되면 해당 강조도 해제합니다.

### 브랜치 툴팁

- 브랜치 배지의 기존 전체 이름 툴팁을 유지합니다.
- Hover 하이라이트 때문에 툴팁이 깜빡이거나 위치가 이동해서는 안 됩니다.
- 기존 배지 충돌 회피·말줄임·세로 나열 정책을 유지합니다.

### Split view

- 각 저장소 열에서 Hover를 독립적으로 처리합니다.
- 한 저장소의 Hover가 다른 저장소를 흐리게 만들지 않습니다.
- 기존 독립 스크롤·공통 자동 갱신·저장소 헤더 드래그 동작을 유지합니다.
- 좁은 열에서도 기존 그래프 표시 정책을 유지합니다.

## 6. 모든 화면의 공통 입력·선택 정책

강조 범위와 불투명도는 넓은 화면·좁은 화면·일반 화면·Split view에서 동일합니다. 화면 너비는 기존 메시지·배지 배치에만 사용하며 커밋 조상 판정을 바꾸지 않습니다.

- Hover 가능한 포인터는 마우스 이동으로 임시 강조합니다. `(any-hover: hover)`와 이벤트의 포인터 종류를 확인하며, 좁은 Split view 열에서도 동작합니다.
- 마우스 클릭·터치 탭 모두 기존 커밋 상세와 해당 커밋의 전체 부모 조상 강조를 함께 표시합니다. 노드·보이는 메시지·기존 버전 아이콘의 클릭/탭 영역은 유지합니다. 숨겨진 메시지에는 별도 입력 영역을 만들지 않습니다.
- Hover는 기존 선택보다 임시 우선합니다. 빈 공간 이동은 최대 100ms 뒤, 포인터 이탈·스크롤·blur·순서/크기 변경은 즉시 Hover를 해제하고, 기존 선택이 남아 있으면 그 조상 범위로 복귀합니다.
- 선택 강조는 Graph의 기존 선택 SHA와 로딩된 데이터에 연결합니다. 상세 닫기·빈 공간 클릭/탭·다른 커밋/저장소 선택 등으로 선택이 해제되면 함께 해제합니다. 선택이 유지되는 크기·열 순서 변경에도 강조를 유지하며 비활성 그래프나 삭제된 커밋에는 적용하지 않습니다.
- 터치 시작·포인터 이동·스와이프·롱 프레스만으로 새 선택 강조를 적용하지 않습니다. 별도의 제스처·롱 프레스 타이머를 추가하지 않으며 기존 스크롤과 취소 처리를 유지합니다.
- 현재 로딩된 데이터만 사용합니다. 미조회 부모의 기존 점선 간선은 강조할 수 있지만 강조를 위해 요청하지 않습니다. 기존 점진 로딩으로 부모가 도착하면 범위를 다시 계산합니다.
- 각 Graph가 독립 처리하므로 한 열의 Hover·선택이 다른 열을 흐리게 만들지 않습니다. 같은 SHA가 다른 저장소에 있어도 기존 저장소별 선택을 따릅니다.
- Actions 도넛은 해당 커밋과 같은 비대상 배율을 적용하며 버전 아이콘의 불투명도, 선택 노드 크기와 상세 조회 요청은 유지합니다. 하이라이트는 추가 API 요청·주기 타이머·DAG 레이아웃 계산을 만들지 않습니다. 빈틈을 건너기 위한 취소 가능한 100ms 단발 해제 예약만 사용합니다.

## 7. 성능

Hover 동작은 빈번하게 발생하므로 불필요한 연산을 최소화합니다.

- Hover 경로 판정은 기존 로딩 데이터만 사용합니다.
- Git DAG 레이아웃을 마우스 이동마다 다시 계산하지 않습니다.
- 브랜치 배지의 기존 시각적 경로와 실제 부모 데이터는 메모이제이션합니다. 커밋 조상 결과는 Hover와 선택에서 공통 재사용하며 최근 두 대상만 캐시해 모든 커밋의 조상 집합이 누적되지 않게 합니다.
- Hover 대상이 실제로 변경된 경우에만 Canvas를 다시 그립니다.
- 새 API 요청이나 주기 타이머를 추가하지 않습니다. 빈 공간의 해제 예약은 그래프당 최대 하나이며 반복 이동으로 기한을 연장하지 않습니다. 같은/다른 대상 재진입·클릭·터치·포인터 이탈·스크롤·blur·화면/모드 변경·언마운트에서 예약을 취소해 늦은 해제가 새 대상을 지우지 않게 합니다.
- 반복적인 React 전체 렌더링을 방지합니다.
- 그래프 자동 갱신 중에도 하이라이트가 정상적으로 갱신되어야 합니다.

기존 Canvas 계측과 개발자 디버그 모드를 통해 성능을 확인합니다.

## 8. 예외 처리

다음 상황에서도 기존 그래프가 정상적으로 표시되어야 합니다.

- Hover 중 브랜치가 삭제되거나 HEAD가 변경됨
- Hover 중 새로운 커밋이 자동 갱신됨
- Hover 중 과거 이력을 추가 로딩함
- 브랜치 경로가 현재 로딩 범위를 벗어남
- 해당 커밋이 여러 브랜치에 공유됨
- Hover 중 화면 방향·크기 변경

- Split view 종료 또는 저장소 변경

## 최종 원칙

**Hover 하이라이트는 특정 브랜치의 Git 이력과 커밋 메시지에 집중하기 위한 기능입니다.**

대상의 노드·연결선·텍스트는 선명하게 유지하고 비대상은 기존 불투명도의 25%로 낮춥니다. 커밋 조상 판정은 모든 화면과 Hover·클릭·탭에서 동일합니다.

Git DAG의 실제 부모 관계를 따르고, 브랜치 이름·레인·색상만으로 경로를 추정하지 않습니다.

## 구현 및 검증 기록

- `branchTracks()`의 기존 순회에서 HEAD와 커밋 SHA의 연결을 유지하고, `graphHover.ts`가 실제 커밋의 부모 관계로 조상 노드·간선을 구성한다. 배지의 first-parent 시각적 경계를 강조 범위에 재사용하지 않으며, `Graph.tsx`가 Hover·선택 대상에 따라 같은 Canvas 불투명도 배율을 적용한다. DAG 정렬·레인 알고리즘은 유지하며 초소형 열 원점의 경계 보완은 아래에 기록했다.
- 같은 HEAD의 배지는 각 이름으로 판정하고, 공유 커밋도 모든 부모 조상을 강조한다. `(any-hover: hover)`와 이벤트의 포인터 종류는 Hover 가능 여부에만 사용한다. 클릭·탭과 Hover는 같은 커밋 조상 계산을 사용한다.
- 회귀 테스트 17개를 추가했으며 전체 소스 테스트 **451개**, TypeScript 검사와 **Production 빌드**가 통과했다. 기준 줄기의 오래된 HEAD·공유 커밋의 공통 조상 정책과 조상 캐시가 최근 두 대상으로 제한됨을 검증했다.
- 로컬 Chromium의 합성 GitHub 응답으로 밝은/어두운 일반 화면, 1440px·640px의 2열, 320px의 8열(열 너비 40px)을 검증했다. 실제 부모가 셋인 병합, 공유 HEAD·모호한 노드, 상대 불투명도와 기존 선 색상·굵기·좌표·배지 크기, Actions 링의 상태·진행률과 버전 아이콘 보존을 확인했다.
- 노드·메시지의 동일 경로, 선택·상세 유지, 전체 이름 툴팁 위치와 동일 배지 안의 반복 이동, 빈 공간·이탈·순서/크기 변경·Split view 종료 시 해제, 숨겨진 메시지의 Hover 영역 부재를 확인했다. Hover 중 추가 API 요청과 DAG 레이아웃 호출은 각각 **0회**였으며, 같은 유효 대상을 유지하는 반복 이동 중 Canvas 다시 그리기도 **0회**였다.
- 브라우저 가상 시계를 이용한 자동 갱신에서 새 HEAD 경로 반영과 브랜치 삭제 시 해제를 확인했다. 과거 페이지 추가 로딩 후 경로 재계산과 스크롤 시 초기화, `prefers-reduced-motion`에서도 동일한 표시를 확인했다.
- 390px 터치 에뮬레이션에서 탭 상세와 모든 부모 조상 강조·선택 해제를 확인하고, 스와이프 스크롤을 유지하며 롱 프레스만으로 새 강조가 생기지 않음을 확인했다. 실제 GitHub 지연·Safari·모바일 실기기/PWA 검증을 대신하는 결과는 아니다.

### 공통 조상 정책 추가 검증

- 1440·390px 일반 화면과 1440·780·390px 2열, 390px 8열에서 같은 커밋의 Hover·클릭 범위가 일치하고, 포인터 이탈 후 선택 범위 복귀·닫기 해제·다른 열의 정상 불투명도를 확인했다. 이 과정의 Hover 추가 API 요청과 DAG 레이아웃 호출은 각각 0회였다.
- 밝은/어두운 390px 터치 화면에서 모든 부모 조상과 기존 상세·아이콘·Actions 링을 확인했다. 780px 2열과 390px 8열에서 동일 SHA를 가진 다른 저장소로 선택을 옮겼을 때 원래 열의 강조가 해제됐다. 숨겨진 메시지 영역은 만들지 않았다.
- 390px 8열의 실제 열 너비가 소수점이고 `clientWidth`는 48px로 반올림되는 경계에서 노드 중심이 다음 열에 놓이던 문제를 확인했다. 기존 초소형 열의 원점 중앙 배치를 48px 경계에도 적용해 노드의 클릭·탭이 원래 열로 전달되도록 보완했다.
- 선택을 유지한 채 과거 페이지가 추가되거나 자동 갱신으로 새 HEAD·브랜치 삭제가 반영돼도 실제 부모 조상을 다시 계산함을 확인했다. 새로 생긴 자손은 흐려지고, 참조 이름이 삭제돼도 남은 조상 선택은 유지됐다. 여러 다른 커밋을 Hover한 뒤 선택 커밋으로 돌아가 이탈할 때도 같은 선택 결과를 재사용해 불필요한 Canvas 다시 그리기가 없었다.
- 비대상 불투명도 배율을 0.25로 조정한 뒤 밝은/어두운 1440px 일반 화면, 390px 터치 일반 화면, 780px 2열의 마우스·터치에서 노드·간선·배지·메시지·SHA/작성자의 상대 배율, 다른 열의 정상 표시, 강조 해제와 Actions 링·버전 아이콘 보존을 다시 확인했다. 전체 450개 테스트와 Production 빌드가 통과했다.

### 도넛 불투명도와 Hover 전환 검증

- 커밋 A → 빈틈 → 커밋 B를 이동할 때 기존 구현에서 빈틈 동안 전체 그래프가 밝아지는 현상을 재현했다. 100ms 단발 해제 예약을 적용한 뒤 짧은 빈틈에서 이전 강조 유지, B의 즉시 적용, 같은 대상 재진입·다음 대상 도달 시 이전 예약 취소, 빈 공간 정지 후 복원과 그래프 이탈 즉시 해제를 확인했다.
- 로컬 Chromium 합성 응답의 9가지 조건에서 검증했다: 밝은/어두운 1440px, 좁은 390px, 780px 2열, reduced motion의 390px 8열, 390px·780px 터치와 Job 수가 확정된/미확정인 진행 상태를 포함한다. 성공·실패·대기·취소·건너뜀·진행 배경 링·진행률 호의 기존 불투명도에 상대 배율 0.25가 적용되고, 색상·진행률 각도·선 두께는 유지됐다. DOM 회전 링은 같은 배율로 표시되며 애니메이션 시작 시각이 바뀌지 않았다. 버전 아이콘은 기존 불투명도를 유지했다.
- Hover로 추가 API 요청이나 DAG 레이아웃 호출이 발생하지 않았고, 저장소 열 간 전환에서도 다른 열의 예약이 현재 강조에 영향을 주지 않았다. 기존 450개 소스 테스트와 Production 빌드가 통과했다. Safari·모바일 실기기/PWA는 미확인이다.
- 해제 예약 중 blur·화면 크기 변경·스크롤·빈 공간 클릭·Split view 종료 시 예약이 취소되고, 선택이 남아 있는 경우 100ms 후 선택 조상 범위로 복귀함을 확인했다.

### 브랜치 배지 조상 누락 검증
